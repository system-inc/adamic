# Adamic 0.1

Status: **approved by Kirk, October 5, 2026**: every decision at the end is his. Task #8vpywxp, written by @system_adamic. Stage 0 is #spf9709.

Adamic 0.1 is the smallest Adamic that is still a real language: numbers, booleans, strings, arrays, maps, plain objects, classes without inheritance, unions you narrow, functions and closures, generics, and modules. It has no exceptions, no async, no input, and no `any`. It is enough to write every program in this document, and every program in this document was run.

## The contract

1. **A program is a set of TypeScript files, judged three ways.** tsc must accept it under the compiler options below. cohere's soundness set (`cohere:adamic`) must find nothing: that set is versionless, and a finding means "the checker's types are not true here". And the Adamic 0.1 compiler must find it inside 0.1's subset (no `async`, no `try`, and the rest of the refusal table): that part knows its version and grows with each release. Pass all three and it's an Adamic 0.1 program. Otherwise it's refused at compile time, with a message that says why and what to write instead. (The split between cohere and the compiler is @system_cohere_lint_fix's design on #drbrp8c, with Kirk.)
2. **Two backends, one meaning.** Stage 0 compiles a program to C (then clang, then a native binary) and to JavaScript (then Node). The JavaScript backend is the oracle.
3. **The oracle.** For every fixture, the native binary and the JavaScript output must produce the same stdout, byte for byte, and the same exit code. When both panic, the first line of stderr must match too, for any panic whose text Adamic owns (an explicit `panic` or a check the compiler inserted).
4. **Checks are visible and the same on both sides.** Where the compiler can't prove something it inserts a check, and it inserts the same check in the JavaScript output. So the oracle also catches a missing check: if native forgets one, Node and native disagree.
5. **Exit codes.** `0` when the program finishes. `70` on a panic (`EX_SOFTWARE` in sysexits.h, "internal software error"). Nothing else in 0.1.
6. **A panic** writes `adamic: panic: <message>` and a newline to stderr and exits 70. Everything the program already wrote to stdout is flushed first. A panic is never caught: 0.1 has no `try`.

## What's in

### Types
- `number` (IEEE 754 float64, exactly JavaScript's), `boolean`, `string`, `null`, `undefined`, `void`, `never`, `unknown`.
- Literal types (`'Circle'`, `42`, `true`), unions, intersections of object types, tuples, `T[]` and `readonly T[]`, `Map<K, V>` and `ReadonlyMap<K, V>` with `string` or `number` keys.
- Object types and interfaces, including `interface ... extends ...` (that's composition of types, not class inheritance), `readonly` properties, and optional properties under `exactOptionalPropertyTypes`.
- Function types, written property-style in interfaces (`readonly admit: (animal: Animal) => string`).
- Generics on functions, interfaces, type aliases and classes. They're compiled by monomorphization: one copy per instantiation. A generic function that would instantiate itself without bound (polymorphic recursion) is refused.
- The type language whole: conditional, mapped, indexed access, `keyof`, `typeof` in type position, template literal types, `infer`, `satisfies`, `as const`. All of it resolves to concrete types before code generation, so it costs nothing at runtime. This is the soul of the language and 0.1 keeps all of it.

### Values and statements
- `const` and `let` (with JavaScript's per-iteration `let` in `for` loops), never `var`.
- `if`/`else`, `for`, `for...of` (over arrays, strings by code point, maps, and a map's `keys()`, `values()` and `entries()`), `while`, `do...while`, `switch`, `break`, `continue`, `return`.
- Function declarations and arrow functions, closures that capture `let` by reference, default, optional and rest parameters, spread in calls and array literals.
- Object literals, and exactly one kind of object spread: one leading spread followed by fields, `{ ...tree, left: newLeft }`. (Why only that one is below.)
- Operators: arithmetic and `**` on numbers; `+` on two numbers or two strings; `<`, `<=`, `>`, `>=` on two numbers or two strings; `===` and `!==`; `&&`, `||` and `!` with JavaScript truthiness; `??` and `?.`; the conditional operator; bitwise operators on numbers (with JavaScript's ToInt32 semantics); compound assignment, `++` and `--`. `||=`, `&&=` and `??=` short-circuit, evaluate the target once, and yield JavaScript's result. They are sound, not a type lie; taste belongs to `cohere:house`, not to the compiler.
- Labeled statements, `break label` and `continue label` preserve JavaScript destinations and run every `finally` they leave. They are sound, not a type lie; taste belongs to `cohere:house`, not to the compiler.
- `void expr` evaluates its operand and yields `undefined`. It is sound, not a type lie; taste belongs to `cohere:house`, not to the compiler.
- The comma operator evaluates operands left to right and yields the last value. It is sound, not a type lie; taste belongs to `cohere:house`, not to the compiler.
- Template literals that interpolate `string`, `number` or `boolean`.
- Narrowing by `typeof`, by `===`/`!==` against a literal, `null` or `undefined`, by a discriminant property, by `instanceof` a class, and by assignment.
- Conditions and `!` use JavaScript ToBoolean, evaluating each operand once. `&&` and `||` short-circuit and return the selected operand value. These forms are sound, not a type lie; taste belongs to `cohere:house`, which still flags them, not to the compiler.
- `switch` cases don't fall through, and a `switch` on a union either covers every member or has a `default`.

### Classes, without inheritance
- Fields with initializers or assigned in the constructor, `readonly`, `private` and `#private`, methods, `static` methods and `static readonly` fields, `implements`.
- `this` only inside methods and constructors, and arrow functions inside them capture it.
- **Classes are nominal and invariant in 0.1.** An instance of one class is never accepted as another class type, and `Box<Dog>` is never accepted as `Box<Animal>`. An instance can always be passed as an interface it satisfies. (Why is below: tsc lets both through.)
- A method can't be detached from its object: `const f = shelter.admit` is refused (the `this` would be lost). Write `(dog) => shelter.admit(dog)`.

### Modules
- Named `export` and `import`, `import type` and inline `type` imports, relative paths with their `.ts` or `.a` extension, and `'adamic'` for the runtime (`panic`).
- Export lists `export { a, b as c }` and named re-exports `export { x } from './m.a'` keep live bindings and JavaScript module evaluation order. They are sound, not a type lie. Taste belongs to `cohere:house`, which still flags them, not to the compiler.
- Star re-exports preserve the checker's exported bindings and JavaScript dependency order. They are sound, not a type lie; taste belongs to `cohere:house`, not to the compiler. A collision is refused by TypeScript with both modules and the name. An explicit named export resolves the ambiguity. Type-only re-exports erase their dependency. Function, class, const and enum re-exports are held to Node.
- No default exports, no namespace imports.
- No import cycles. Module bodies run in ECMAScript order (depth-first, dependencies first), and top-level statements are allowed anywhere.

## The soundness rules: what the gate adds to tsc

tsc in strict mode is not sound, on purpose. These are the holes 0.1 closes, each one proven open on tsc 6.0.3 with the strict options below: tsc exits 0, then Node fails at runtime. The rule names are cohere's: existing rules keep their upstream names, and new ones are `adamic/`. @system_cohere_lint_fix's design on #drbrp8c proves twenty probes (h01 to h20) and agreed with every hole here. It also found four this table first missed (the last four rows).

| cohere rule(s) | The hole, as tsc 6.0.3 accepts it | State |
|---|---|---|
| `no-explicit-any`, `no-unsafe-assignment`, `no-unsafe-argument`, `no-unsafe-return`, `no-unsafe-call`, `no-unsafe-member-access` | `any` switches the checker off for everything it touches | exist |
| `adamic/no-unchecked-cast` | `load() as User` on an `unknown`, `x as unknown as T`. Upcasts pass to the relation rules, and checked downcasts are counted, not reported | new |
| `no-non-null-assertion` | `ages.get('Ahra')!` reads `undefined` as a number | exists |
| `adamic/no-type-predicate` | `pet is Cat` is trusted and never checked; its body can say anything | new |
| `adamic/invariant-mutable` | `Dog[]` accepted as `Animal[]` (assigned, passed or returned), `{ pet: Dog }` as `{ pet: Animal }`, `Map<string, Dog>` as `Map<string, Animal>`, and the same through a type parameter's constraint (`const pack: Pack = narrow`, `Narrow extends Pack extends Animal[]`) or an intersection (`Dog[] & { tag }` as `Animal[] & { tag }`), or a covariant `readonly` field seen again as a writable one (tsc ignores `readonly` when it relates properties); write a cat through the wider name and the dog array holds a cat | new; stage 0 refuses it too, at every place a value goes into a typed slot, including a default, a class field, a shorthand property, a spread, `as`, a union of either side, a method's results and parameters, a class, every element of a tuple, and a wider type tsc inferred for a conditional, a literal or a return; a copy nothing else holds (`slice()`, `map`, `new Map()`) is judged only by what it holds (`internal/lower/invariance.go`) |
| `adamic/nominal-class` | `DogShelter` accepted as `AnimalShelter` (method parameters compare bivariantly when the target is a method), an object literal as a class type, and `Box<Dog>` as `Box<Animal>`, even with a private field | new, needs the checker's relation |
| `method-signature-style` (`property`) | `interface { admit(animal: Animal): string }` compares bivariantly; the property form `admit: (animal: Animal) => string` is checked properly | exists |
| `adamic/no-optional-widening` | `{ x, y: 'surprise' }` seen as `{ x }`, then as `{ x; y?: number }`: `y` is typed `number \| undefined` and holds a string | new |
| `unbound-method` | a detached method's `this` is typed as the class and is `undefined` at runtime | exists |
| `adamic/single-spread` | `{ ...a, ...b }` and `{ x: 1, ...b }`: `b` carries an `x` its type doesn't show, so the result's `x` is typed `number` and holds a string. Only one leading spread followed by fields is sound | new |
| `adamic/no-definite-assignment` | `balance!: number` is never assigned and reads `undefined` | new |
| `ban-ts-comment` (all four directives) | `// @ts-ignore` silences the checker on the next line | exists |
| `no-unsafe-function-type`, `no-unsafe-call` | the `Function` type calls anything with anything | exist |
| `no-unsafe-declaration-merging` | an interface merged into a class claims fields the class never sets | exists |

Non-boolean conditions are sound, not a type lie. Ruling 2, final, by @system_adamic accepts JavaScript's exact semantics. Taste belongs to `cohere:house`, which still flags these forms, not to the compiler. A `switch` on a union still must be exhaustive or have a `default` (`switch-exhaustiveness-check`).

Taken together: a mutable location (an array element, a mutable property, a map value, a class's type argument) is invariant, and a `readonly` one is covariant, the same as tsc already gets right for `readonly T[]`. That's one rule seen from five sides, and it's the price of "Adamic believes your types". **Immutable by default is how you stop paying it**: `readonly` everything and the variance comes back for free.

|---|---|---|
| `any` | It has no proven type, so nothing after it can be trusted | Never. `unknown` and narrowing |
| `as` except `as const`, upcasts, and **checked downcasts** | A cast the runtime can't check is a type the compiler would have to trust. A downcast to a member of a union is checkable (the tag is there) and becomes a check that panics: `shape as Circle` | #bw3xg7c decides the rest against the survey |
| Non-null `!` and definite assignment `field!: T` | A crash with no reason in it. Write `?? panic('why it cannot be missing')` instead, and the crash explains itself | #bw3xg7c may bring it back as a checked unwrap, if the survey's counts (6.4 per 1,000 lines in tsc's source) argue for it |
| User-defined type guards `x is T`, and `asserts x is T` | Trusted, never checked, and the body can lie (refusal 4 below) | When the compiler can verify the body is exactly a narrowing |
| `throw`, `try`/`catch`/`finally` | Unwinding through reference counting needs cleanup paths in every frame; 0.1 doesn't pay for that. Errors are values (program 8), invariants are panics | 0.2, with unwinding designed in #w318mqs; designed in docs/memory.md ("Exceptions"), and stage 0 already lowers a first cut (`throw new Error`, `try`, `catch`, `finally`, #zek5q21) |
| `async`, `await`, `Promise`, generators | Coroutines lower to state machines in C; that design belongs with the concurrency model (#p286ycm). 0.1 has no I/O to wait on | After #p286ycm |
| Class `extends`, `super`, `abstract`, `protected` | Overriding brings method variance, constructor order and dispatch tables. Interfaces carry polymorphism in 0.1 | 0.2 |

| Getters and setters | In 0.1 a property read is a load. That keeps the mutation and aliasing analysis (#5jck546) honest | 0.2, lowered as methods |
| Decorators | Runtime metaprogramming that replaces class members after the fact | Probably never in this form |
| `eval`, `new Function`, the `Function` type | No compiler at runtime in a native binary | Never |
| Expandos, `delete`, `Object.defineProperty`, prototype mutation, `in`, `for...in` | A shape is fixed when the object is made, and there is no key reflection | Never for mutation; reflection is a later question |

| Function overloads | The implementation signature is only loosely checked against each overload | Unions cover 0.1 |

| Input: arguments, stdin, files, environment | 0.1 programs are closed, so every fixture's output is a pure function of its source | Arguments and files opened in 0.2, because stage 1 (cohere) reads them: `programArguments()`, `readTextFile(path)` and `writeTextFile(path, text)` from `'adamic'` (below). Stdin and the environment are still to come |

## Semantics that differ from JavaScript

**None on purpose.** A 0.1 program means exactly what Node does with it, through the JavaScript backend. There are two exceptions. The first: **the depth at which recursion runs out of stack** differs (Node gives up at about ten thousand frames; a native stack goes much deeper). Both sides panic, but not at the same depth, so fixtures stay well under it, and the native runtime must turn a stack overflow into a panic with a guard page, never a bare segfault.

The second, which a program opts into by importing `Weak` from `'adamic'`: **a `Weak` read after its target's last strong owner is gone is `undefined` natively, while on Node the collector keeps the object** as long as the `Weak` points at it. A read the checker had narrowed to present panics natively instead of reading freed memory. Reading a `Weak` only while something holds its target strongly (a child's parent pointer, while the tree is held) means the same on both sides, and the oracle's fixtures do only that; `internal/oracle/weak_test.go` pins the difference itself, each side to what it's meant to do. Decided by @system_adamic, October 2026 (#gsz351g); the design is in docs/memory.md.

Matching Node is real work in a handful of places. These are the traps, so stage 0 meets them on purpose:

- **Strings are UTF-16 to the program.** `length`, indexes, `slice`, `charCodeAt` and `<` all count and compare UTF-16 code units, because JavaScript does. How the runtime *stores* a string is its own business (UTF-8 with an ASCII fast path is the lean, and WTF-8 handles lone surrogates), but the behavior is fixed. Program 10 pins it: `'\uFFFF' < '🌍'` is `false` in JavaScript, and a naive UTF-8 byte compare says `true`.
- **Lone surrogates print as U+FFFD.** Node writes a lone surrogate to stdout as the bytes `EF BF BD` (tested on Node 24.14.1). Program 10 prints one.
- **Number to string** is ECMAScript's Number::toString: the shortest digits that round-trip, closest to the value, ties to even, with exponent form at 1e21 and below 1e-6. `toFixed` is exact. Program 3 prints `26.568583470577035`.
- **`Math.round` rounds half up** (`Math.round(-2.5)` is `-2`), not half away from zero like C's `round`.
- **`Math.pow` and `**` aren't correctly rounded**, so libm and V8 can differ in the last bit. The runtime has to carry V8's algorithm. This is an inference; a pow sweep through the oracle settles it. `sqrt` is correctly rounded everywhere, so it's safe. The rest of `Math` (sin, cos, exp, log and kin) waits for 0.2 and a port of the same fdlibm code V8 carries.
- **Sort is stable, and it's V8's algorithm.** `sort` requires a comparator in 0.1 (the default sorts numbers as strings: `[10, 9, 1].sort()` is `1,10,9`). With a comparator that isn't consistent, the order depends on the algorithm, so the runtime uses TimSort the way V8 does. An array of `number | undefined` sorts every `undefined` to the end without passing one to the comparator, as V8 does: the numbers are taken out, sorted and written back, then the `undefined`s after them.
- **Maps iterate in insertion order**, and entries added during iteration are visited while deleted ones aren't. The runtime's ordered hash table follows JavaScript's rules.
- **`console.log` takes exactly one string.** With one argument Node prints it as-is: `'100%%'` prints `100%%`, and `'%s'` prints `%s` (tested). Any other form goes through `util.format` and `util.inspect`, which 0.1 refuses rather than reimplements.
- **Output lands as Node's does.** Node writes each `console.log` at once (to a file, a terminal, and on Linux a pipe). Native buffers stdout, 64 KiB at a time, and flushes it everywhere the difference could be seen: before every write to stderr, which may be the same file, before a file is read or written, its status taken or a directory listed (it may be stdout or stderr themselves, its size what's been written, or stdin waiting on a prompt just printed), before a panic's message, at exit, after every line when stdout is a terminal, and when SIGTERM, SIGINT or SIGHUP stops the program, which then ends killed by that signal, as Node's does. SIGKILL can't be caught, and what the buffer holds then is lost. A reader of a pipe gets the same bytes in larger pieces. When stdout's reader is gone, Node doesn't stop: the program runs on with its output dropped, stderr is still written, and it ends with exit 70 (the oracle's runtime makes a stream's error exit 70). Native does the same, and ignores SIGPIPE, as Node does, rather than die of it. `internal/oracle/output_test.go` holds all of it: stdout and stderr on one file and on one pipe, stdout a pipe already closed, stdin answered only once the prompt is seen, and each of the three signals sent from outside, under the sanitizers.
- **Array writes** are allowed only at an existing index. Writing past the end (or a negative or fractional index) panics, in both backends, because JavaScript would quietly grow the array or make a hole. `push` is how you append. `length` can't be assigned.
- **Library calls that throw in JavaScript panic.** `'x'.repeat(-1)` is a panic with exit 70 on both sides. For these the oracle compares stdout and the exit code, not V8's error text.
- **Identity is preserved under reuse.** Reference counting may reuse an object in place only when nothing else holds it, so `===` on objects means exactly what it does in JavaScript. Program 9 pins it: the subtree `before` still holds is shared, not rebuilt and not mutated.

## The standard library for 0.1

Shipped as Adamic's own `.d.ts` with `noLib`, so anything not listed here doesn't exist as far as the checker is concerned. The library refuses by omission; no rule needed.

- **Output:** `console.log(message: string)`, `console.error(message: string)`.
- **Runtime:** `panic(message: string): never` from `'adamic'`.
- **A string's UTF-8, from 0.2:** `utf8Length(text: string): number` and `utf8At(text: string, index: number): number` from `'adamic'`, the text's UTF-8 as `TextEncoder` writes it (a lone surrogate is U+FFFD's three bytes), read in place: natively nothing is copied, since a string is stored as UTF-8 already. `utf8At` panics with `RangeError: utf8At index <index> is not a byte of a text of <length> bytes` where the index isn't one of its bytes. They're what a port of Go code that indexes a string's bytes (`text[index]`) reads; stage 1's gitignore glob is the first.
- **Input, opened in 0.2:** from `'adamic'`, `programArguments(): readonly string[]`, the arguments after the program as `process.argv.slice(2)` gives them (a new array each call), and `readTextFile(path: string)`, which is `{ readonly kind: 'Ok'; readonly text: string } | { readonly kind: 'Error'; readonly message: string }`. A failure is a value, since there are no exceptions yet. The text is decoded exactly as Node's `readFileSync(path, 'utf8')` decodes it: invalid bytes become U+FFFD by the WHATWG decoder's rules, and a byte-order mark stays, as U+FEFF; arguments are decoded the same way. A relative path is from the working directory. The message is Adamic's own words, the same on every platform, where Node's aren't: `cannot read <path>: no such file` (a missing file, or a path through something that isn't a directory), `... permission denied`, `... is a directory`, and `... failed` for anything else, a NUL in the path among them. The oracle holds all of it to Node (`internal/oracle/input_test.go`), with a sweep over malformed UTF-8.
- **Output to a file, opened in 0.2:** from `'adamic'`, `writeTextFile(path: string, text: string)`, which is `{ readonly kind: 'Ok' } | { readonly kind: 'Error'; readonly message: string }`, written as Node's `writeFileSync(path, text)` writes it: the file made (mode 0666 before the umask) or emptied, then the text as UTF-8, a lone surrogate as U+FFFD. Its messages are the same words with `cannot write <path>`, except that a path whose directory isn't there is `no such directory`. The oracle gives each run a directory of its own and compares what every run leaves there, each file's name, bytes and permissions.
- **The file system a walk needs, opened in 0.2:** from `'adamic'`, `readDirectory(path)`, which is `{ readonly kind: 'Ok'; readonly names: readonly string[] } | { readonly kind: 'Error'; readonly message: string }`, the names exactly as Node's `readdirSync` gives them on the same machine (libuv sorts them by their bytes, hidden ones included, without `.` and `..`, and each is decoded as UTF-8 after the sort); and `fileStatus(path)`, which is `{ readonly kind: 'Ok'; readonly type: 'file' | 'directory' | 'other'; readonly size: number; readonly symbolicLink: boolean } | { readonly kind: 'Error'; readonly message: string }`: the type and size of what the path names with a symbolic link followed, as `statSync` sees it, and whether the path is itself a link, as `lstatSync` sees it. A link to nothing is no such file, as `statSync` says. Messages are Adamic's words: `cannot read directory <path>: no such directory`, `... not a directory`, `... permission denied` and `... failed`, and `cannot read status of <path>: no such file`, `... permission denied` and `... failed`. `walk.a` holds them to Node, with links, a directory that can't be listed and one that can't be entered.
- **Number:** `toString()`, `toFixed(digits)`, `Number.parseInt(text, radix)`, `Number.parseFloat(text)`, `Number.isNaN`, `Number.isFinite`, `Number.isInteger`, `Number.MAX_SAFE_INTEGER`, `Number.MIN_SAFE_INTEGER`, `Number.EPSILON`, `NaN`, `Infinity`.
- **String:** `length`, `[index]` (gives `string | undefined`), `at`, `slice`, `indexOf`, `lastIndexOf`, `includes`, `startsWith`, `endsWith`, `split(separator: string)`, `trim`, `trimStart`, `trimEnd`, `repeat`, `padStart`, `padEnd`, `charCodeAt`, `codePointAt`, `String.fromCharCode`, `String.fromCodePoint`, `toUpperCase`, `toLowerCase`, `normalize` (NFC, NFD, NFKC and NFKD), `+`, template literals. Case mapping is Unicode's full, locale-independent mapping (`ß` uppercases to `SS`, and `Σ` lowercases to `ς` at the end of a word), and both it and normalization use tables generated for the Unicode version Node reports (`process.versions.unicode`, 17.0 on Node 24.14.1).
- **Array:** literals, `Array.from({ length }, (_, index) => ...)`, `length`, `[index]` (gives `T | undefined`), `at`, `push`, `pop`, `slice`, `concat`, `indexOf`, `includes`, `join`, `map`, `filter`, `reduce` (with an initial value), `some`, `every`, `find`, `findIndex`, `forEach`, `sort(compare)`, `reverse`, spread.
- **Map:** `new Map<K, V>()` and `new Map(pairs)` from pairs written out, an array of `[key, value]` tuples, another Map or its `entries()`; `get` (gives `V | undefined`), `set`, `has`, `delete`, `clear`, `size`, `forEach` (value, key, then the map), `keys`, `values`, `entries`, `for...of`, spread (`[...map]`, `[...map.keys()]`, `[...map.values()]`). Keys are strings, numbers, booleans, or objects, arrays, maps and functions, each its own key, by identity. A tuple written out (`[key, value]`) is a value wherever the checker types it a tuple, and a fixed tuple's `length` is its type's. `pairs[0]?.[0]` reads a tuple that may be missing. `const [a, b] = tuple` and `const { x, y: other } = object` destructure, and so does a parameter, `([key, value]) => ...` or `({ x, y }) => ...`, not yet beside a parameter with a default. A value may be `number | undefined` (a key held with `undefined` is there: `has` says so, and `get` gives `undefined` for it and for a missing key alike), and `reduce` may carry `number | undefined`.
- **Set, opened in 0.2:** `Set<T>` and `ReadonlySet<T>` of strings, numbers, booleans, objects, arrays, maps or functions: `new Set<T>()` and `new Set(iterable)` from an array, a string (its code points), another Set, a Map (its entries) or what `keys()`, `values()` and `entries()` give; `add` (which is the set), `has`, `delete`, `clear`, `size`, `forEach` (each element twice, then the set), `for...of` and `keys()`, `values()` and `entries()` in insertion order, and spread. Strings and numbers compare with SameValueZero (`NaN` is found, and `-0` goes in as `+0`); an object, an array, a map or a function is its own element, found by identity, as `===` finds it. Iteration is live as a Map's is: an element added during a loop is visited, one deleted before its turn isn't, and after `clear` the loop goes on with whatever is added. Natively a Set is the Map's own table with its values unused. Not yet: a Set's entries outside a `for...of`.
- **Math:** `abs`, `ceil`, `floor`, `round`, `trunc`, `sign`, `min`, `max`, `sqrt`, `pow`, `PI`, `E`.

Constant module enums are accepted as JavaScript enum objects, including numeric reverse mappings. Stage 0 supports string values and small integer values. Computed initializers, merged, local and const enums, prototype-changing member names and other numeric reverse keys say `NotYet`. The source oracle uses Node's own TypeScript transform mode so enum output is decided outside Adamic.

## Compiler options

Every Adamic 0.1 project compiles under these, and stage 0 sets them itself rather than trusting a tsconfig.json to have them:

```json
{
	"strict": true,
	"noUncheckedIndexedAccess": true,
	"exactOptionalPropertyTypes": true,
	"noImplicitReturns": true,
	"noFallthroughCasesInSwitch": true,
	"erasableSyntaxOnly": false,
	"verbatimModuleSyntax": true,
	"allowImportingTsExtensions": true,
	"moduleDetection": "force",
	"noLib": true
```

```ts
class Stack<Item> {
	private readonly items: Item[] = [];

	push(item: Item): void {
		this.items.push(item);
	}

	pop(): Item | undefined {
		return this.items.pop();
	}

	size(): number {
		return this.items.length;
	}
}

const openers = new Map<string, string>([
	[')', '('],
	[']', '['],
	['}', '{'],
]);

function isBalanced(input: string): boolean {

	for (const character of input) {
		if (character === '(' || character === '[' || character === '{') {
			stack.push(character);
			continue;

		}

	return stack.size() === 0;
}
```

### 9. A persistent tree

Immutable insert with structural sharing. Each `{ ...tree, left }` is the one spread form 0.1 allows. When nothing else holds `tree`, reference counting can reuse the node in place; here `before` holds the old tree, so the path is copied and the untouched right subtree is shared, which the last line proves.

`09_tree.ts`

```ts
interface Tree {
	readonly value: number;
	readonly left: Tree | undefined;
	readonly right: Tree | undefined;
}

function insert(tree: Tree | undefined, value: number): Tree {
	if (tree === undefined) {
		return { value, left: undefined, right: undefined };
	}
	if (value < tree.value) {
		return { ...tree, left: insert(tree.left, value) };
	}
	if (value > tree.value) {
		return { ...tree, right: insert(tree.right, value) };
	}
	return tree;
}

function collect(tree: Tree | undefined, into: number[]): void {
	if (tree !== undefined) {
		collect(tree.left, into);
		into.push(tree.value);
		collect(tree.right, into);
	}
}

function height(tree: Tree | undefined): number {
	return tree === undefined ? 0 : 1 + Math.max(height(tree.left), height(tree.right));
}

let tree: Tree | undefined = undefined;
for (const value of [50, 30, 70, 20, 40, 60, 80, 30, 65]) {
	tree = insert(tree, value);
}
const before = tree;
tree = insert(tree, 10);

const values: number[] = [];
collect(tree, values);
console.log(values.join(' '));
console.log(`height ${height(tree)}, was ${height(before)}`);
console.log(`right subtree shared: ${tree.right === before?.right}`);
```

```
10 20 30 40 50 60 65 70 80
height 4, was 4
right subtree shared: true
```

## Decisions for Kirk

Kirk decided every one on October 5, 2026: the first two as written, and the rest by taking the recommendation.

1. **The file extension. Decided by Kirk, October 5: `.ts` and `.a`, both.** A `.ts` file that passes the gate already is Adamic, and Node runs it as-is (every output above came that way). `.a` is ours: one letter, like `.c`. It was Unix's extension for static libraries, which is why GitHub's C and C++ `.gitignore` templates still list `*.a`, so stage 0 asks git whether each source is ignored (`git check-ignore`) and refuses to build one that is, saying why. The runtime never ships as a `.a`. Two consequences for stage 0: tsc doesn't know `.a`, so stage 0's in-process host tells typescript-go that `.a` is TypeScript; and Node runs a `.a` file as plain JavaScript (fine for `dedication/dedication.a`, a syntax error at the first type), so for `.a` files the oracle runs through the JavaScript backend. Editors need cohere's VS Code extension to claim `.a`.
2. **The Go module path. Decided by Kirk, October 5: `github.com/system-inc/adamic`,** matching the repo, like `github.com/system-inc/cohere`. A vanity path (a domain of our own) can still be weighed before anything goes public.
3. **Decided:** **`number` is float64 only.** Splitting int and float would change what programs mean (overflow) or add a type JavaScript can't represent, and either one breaks the oracle. The compiler can still use machine integers wherever range analysis proves it can't tell the difference.
4. **Decided:** **`!` is refused, and `?? panic('reason')` replaces it.** The alternative is a checked `!` (Swift's way), which tsc's own source would want; #bw3xg7c can revisit with counts.
5. **Decided:** **Checked downcasts to union members are in 0.1** (`shape as Circle` panics if it isn't one). Every other cast is refused.
6. **Decided:** **Panics exit 70** and print `adamic: panic: <message>`.
7. **Decided:** **0.1 has no input:** no arguments, stdin, files or environment. Closed programs keep the oracle exact. 0.2 opens them, since stage 1 needs them.
8. **Decided:** **Classes are nominal and invariant** in 0.1 (the soundness rules above).
9. **Decided:** **No exceptions in 0.1.** Errors are values and invariants are panics; `try` comes with unwinding in 0.2.
10. **Decided:** **The runtime package is named `adamic`.** The JavaScript backend imports `panic` from it. Nothing gets published to npm without you; until then the JavaScript backend vendors it.
