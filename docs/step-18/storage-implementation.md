# Ruled optional callable storage implementation

Task #tvq1eqm, step 18. The storage-contract proposal was approved with three
requirements: a nullish receiver skips the whole continuous chain; the value
selected before arguments is the one invoked; a present non-callable in .ts
stops with exit 70 after arguments, while .a requires proof or refusal.
Weak/unchecked callable storage and dynamic descriptor mutation remain NotYet.

## Shape 1: function-valued field

Optional field invocation now retains its selected closure and object, including
ordinary function expressions with a represented dynamic receiver. Lexical
arrows preserve their captures. Explicit source `this` parameters do not consume
an ordinary argument. Receiver-dependent data-field reads cannot silently become
bound closures or lose their receiver through a structural view.

Runtime selection reads the slot's representation tag before following a pointer.
A non-callable is recorded as a present invalid selection, so argument effects
still execute before the ruled panic. A checker narrowing over a union slot is
Refused in .a; the paired .ts witness, generated temporarily from the .a source,
prints `arguments` and stops with exit 70. Native and JavaScript both print
`adamic: panic: TypeError: optional call value is not callable`.
Original Node prints `arguments`, then exits 1 with TypeError; the source oracle
normalizes that uncaught TypeError to exit 70. The shape-1 commit tightened the
source exit assertion after its initial green run using raw Node's exit rather
than the oracle normalization. Shape 4 corrects that test assertion; the compiler
behavior was unchanged.

Dependency: compiler/per-backend-stops 8273e6f5 is not on this base. No backend
divergence is needed: this fixture's two backend outcomes agree exactly, and its
Node-to-Adamic ruled difference is pinned by TestStep18StorageTypeLie. Existing
unchecked casts and callable view contracts were not opened.

Controls: field.a agrees with Node in both backends, native ASan/UBSan and
LeakSanitizer. The existing 25 admitted step-18 fixtures pass, as do scoped lower
boundaries, the moved namespace-method fixture, touched-package vet and new-file
a-check. Six overlays are caught by behavior assertions rather than compilation:
receiver lost, field reselected, arguments before guard, non-callable silently
exits 0, non-callable stops before arguments, and .a non-callable storage admitted.
The initial silent-exit overlay had an undeclared C exit call; it was corrected
and only its successful compilation/runtime mismatch is credited.
Reproduce with `python3 docs/step-18/run-storage-mutants.py`; logs and selectors
are recorded in storage-mutants.json. Tests source the existing toolchain and
use workspace-backed TMPDIR/GOTMPDIR. Test output is written directly to logs.

## Shape 4: optional method

Shape 1 is 6b3238d4a71416e1d7d13773cb90111d7a1c7c2b. Optional-method
selection preserves own/prototype selection and the receiver before arguments.
A required member call inside a continuous optional chain now carries an explicit
required-callable flag: only its earlier receiver guard short-circuits it, and a
missing or invalid callable stops after arguments rather than dereferencing it.

optional-method.a holds inherited class methods, absent members, explicit
undefined fields, receiver binding and `a?.b.report(argument())` to Node in both

All six shape-1 mutants were rerun and caught. Scoped lower/IR/flow checks, vet
and changed-file a-check pass. The source type-lie expectation now pins the
oracle-normalized Node TypeError bytes; the shape-1 raw-exit assertion correction
is recorded above. Both backend loud stops still match exactly.

Linux counts add optional-method.a only; no existing row changes. Tsc's

## Shape 2: getter returning a function

Shape 4 is 8f26a917669393c9f17f56e0325889a04eb75a26. Callable
accessor selection now retains the receiver, invokes the represented getter once,
then checks its returned callable before arguments. Class, literal and structural
views share that dispatch; lexical arrows and ordinary function receivers retain
their different meanings. A throwing getter leaves before arguments or later
try-body effects. Getter signatures are validated against the closure return ABI.

The JavaScript path uses accessor metadata and the existing static-method table.
Both were exposed by Node regressions and fixed before this shape was pushed.
Known data selections are retained; getter results are already owned. A method
or absent selection no longer adds a redundant retain(NULL) operation.

Dynamic receiver declarations now prove the owner's required members, nominal
relations and writable-slot relations, without fresh-literal excess-property
checking. The erased-this receiver-contract mutant admits a missing member and
is caught by the exact refusal test. Data fixtures declare readonly receiver
reads explicitly, preserving the readonly relation. Two precise runtime selection
readers are registered in the call-target audit, which initially rejected their
unregistered reads; no target analysis was waived.

Controls: getter.a and getter-throw.a agree with Node in both backends with
ASan/UBSan and leak checks. Existing step-18 and accessor controls and every moved
count row agree with Node. Lower/IR/flow checks, vet and changed-file a-check pass.
All ten current overlays are caught: the original seven, getter twice, delaying
a getter throw, and erasing the receiver contract. The former getter NotYet
boundary is retired in favor of these positive and failure witnesses.
No production tsc callable-getter occurrence was established by the source census;
this implements its ruled storage shape, not a claimed production-stop retirement.
