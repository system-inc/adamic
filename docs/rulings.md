# Adamic rulings ledger

This is every language ruling made since October 5, 2026, in one place, so a new mind can answer "does Adamic allow X, and what pins it?" without reading a hundred task threads. docs/0.1.md is the spec; this ledger indexes each ruling with where it was made, the spec section that states it, and the test that goes red if it breaks. A ruling that isn't here is a ruling the language will contradict, because nobody will know to keep it. Language (@system_adamic_language) keeps this file: a new ruling lands here in the same change that lands it in the spec or the compiler.

How to read an entry. The kinds are Accept, Refuse (a compile-time refusal with a fix), Check (an inserted runtime check that panics, exit 70), NotYet (intended, not built, stopped at compile time), Run-time NotYet (intended, not built, and only knowable at run time: an exit-70 stop from a closed allowlist, after exactly Node's output, never a wrong answer), and Meaning (what a construct means relative to Node). `.a` is code written for Adamic, proven or refused; `.ts` is existing TypeScript, tsc's own source included, proven or checked. Sources are task ids (with the comment id in parentheses) and doc lines; "#bw3xg7c" is the escape-hatch umbrella task. Test paths are from the repository root; `cohere/...` paths are in the cohere submodule. `NONE (implemented at ...)` means the code exists and no test pins it; `NONE (not found)` means neither turned up in a search of the tests and of internal/lower.
