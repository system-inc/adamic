These do not run natively. Stage 0 or the checker refuses them before a binary exists, so they are not oracle fixtures. The fixtures that do lower agree with Node.

Nested function capturing a named function expression's name:

source:
const walk = function walk(n: number): number {
	const step = function (): number { return walk(n - 1); };
	return n <= 0 ? 0 : n + step();
};
console.log(`${walk(5)}`);

Node exit 0, stdout:
15

native:
Adamic 0.1 refuses 'walk', a variable a function value captures and can be reached from what it holds, so the function holds the variable and the variable holds the function: a cycle reference counting can't free; write the function as a function declaration (function walk() {}), which captures nothing, or declare the variable Weak<...> and keep the function somewhere strong (adamic/cycle-capable)

Direct calls through the inner name, and passing that name into a callback, do lower and agree. The refusal is the nested function capturing the binding.

delete during for...in:

source:
const box = { a: 1, b: 2, c: 3 };
const keys: string[] = [];
for (const key in box) {
	keys.push(key);
	if (key === 'a') {
		delete box.b;
	}
}
console.log(keys.join('|'));

Node exit 0, stdout:
a|c

The checker also requires the deleted property to be optional. With an optional property, stage 0 still refuses:

Adamic 0.1 refuses delete; an object's shape is fixed; use a Map for keys that come and go

What Adamic does allow is clearing a present field to undefined. The key stays in the enumeration. That case is library_for_in_live.a and agrees with Node.

A string key added by a spread the source does not already have:

source:
const early = { b: 1, '2': 2, z: 3 };
const later = { ...early, added: 4, '10': 10 };
const keys: string[] = [];
for (const key in later) {
	keys.push(key);
}
console.log(keys.join('|'));

Node exit 0, stdout:
2|10|b|z|added

native:
stage 0 can't lower a spread that adds a field the source doesn't have yet

Assigning a wider plain object to a narrower binding, then enumerating, does lower. The later object's integer and string keys are what for...in prints. That case is library_for_in_keys.a and agrees with Node.
