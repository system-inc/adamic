Implementation and soundness
The guard was in internal/lower/class.go, callOrMethod, immediately before its structural-signature fallback. It rejected any MethodSignature when staticGlobals was nonempty. A structural method signature can describe an instance or a constructor's static side, so choosing a method by signature/name from an arbitrary class would be unsound.
Conservative assumption: a structural signature identifies neither side. The existing callClosure/property-method interface machinery resolves against the receiver's named map, preserving actual this. Static allocations now install their own inherited named method map, while nominal calls keep existing virtual slots. Instance/static maps remain separate even when both sides share a method name. Own closure fields keep their existing priority.
The JavaScript backend additionally needed to preserve the static named map when turning storage into a constructor function, separately from the live parent prototype that provides static field inheritance. A WeakMap keyed by the actual constructor stores it. Main allocation maps are discovered before their declarations are emitted. The selected method is captured before evaluating arguments.
No protected lower.go, emit.go, native.go, oracle_test.go, or cohere source was edited. The necessary JavaScript backend change is included to satisfy the requested two-backend oracle.
