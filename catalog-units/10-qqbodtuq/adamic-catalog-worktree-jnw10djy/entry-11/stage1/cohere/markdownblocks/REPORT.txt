Scope and implementation

Same branch: codex/stage1-markdown-blocks. Parent 250158ed66d8c6ed5306b0a87de2bf87b5852a85.
This unit selects the event kernel and mdast constructor because construction
composes with the existing printer without requiring an embedded-language parser.
Only stage1/cohere/markdownblocks changed. No compiler or prior inline edits.

Read CLAUDE.md and actual cohere tokenizer/types, mdast constructor/extensions,
node and ParseMarkdown sources. TokenArena and TokenizerEvents port identity,
points, consume, enter/exit, checkpoints/rollback, skips, chunks and serialization.
Controlled programs run the actual private Go and original fork tokenizer effects.
They do not replace the complete construct factory, grammar, resolver ordering,
subtokenization or streaming. The fork adapter infers terminal private consumed
and stack state; all its public observations come from the actual engine.

MdastCompile constructs the complete non-MDX Go node arena from pre-compilation
resolved lexical events and raw context chunks. It implements list-item event
insertion, spread inference, every core and extension handler, buffered text,
references/escapes, tables, tasks, footnotes, delete, autolinks, math, wiki/liquid.
ParseFrontMatter recognizes, blanks and inserts front matter natively. Its blanked
source is compared independently; embedding is absent at this layer.

The transport contains token identity, type, flags, five point fields, event
order and raw source streams. No constructed AST, inserted listItem events,
inferred list spreads or sliced token strings are supplied. Actual Go
ParseMarkdown and actual fork full source parsing independently supply expected
canonical trees. Both actual compilers additionally consume the same transport.
Go offsets convert to UTF-16 through its byte-offset map, not inferred AST points.
Canonical preorder compares every Go construction field and its presence/null
flags, children and coordinates. Extra original JavaScript object properties,
HAST data and originalLabelText absent from Go are outside this typed projection.
Front-matter point-valued start is not a list start integer. Native preprocessing
and printer AstPath remain separate arenas and are not integrated with this tree.
A complete native source parser or formatter is NOT established by these checks.

The parser also needs a representation change before a literal port lowers

Micromark represents a state as func(code Code) State, nil at completion, with
captured mutable frames and mutually referring state closures. The minimal probes
separate three facts:

1. gaps/1_recursive_state.ts: Node prints 35 twice. load succeeds; lower returns
   NotYet with exactly "a function inside a function (a closure)".
2. gaps/2_state_arrow_cycle.ts: Node prints 35 twice. A mutable arrow-state cell
   that its closure captures is Refused by Adamic 0.1 as a reference-counting cycle.
   This is a language refusal, not a compiler feature promised to arrive later.
3. gaps/3_recursive_callable.ts: noncapturing top-level recursive callable state is
   supported. Source Node, the JavaScript backend, native ASan/UBSan and native
   LeakSanitizer all agree on 1 then 0, with zero exit and no stderr/leaks.

The recursive callable type itself is not a blocker. Explicit state/frame IDs,
owned arenas and appropriate weak back references are a possible porting approach;
that complete engine transformation was not done. I did not replace the micromark
parser with an approximate line scanner, hand original parsing off to Node/Go in an
alleged native formatter, or edit compiler-owned files to hide the representation gaps.
