# Per-rule worker prompt

This is a draft for a coordinator to fill from one inventory entry after prerequisite helpers have landed. Do not start all rules against the current shared lint.ts. Land shared contracts first, then give workers disjoint files and let one integrator own the dispatcher and manifest. Existing-selector rules are verification or completion jobs until their branch reports establish what remains.

## Template

Unit: port `{rule}` from pinned Go cohere `{cohere_commit}` to Adamic. Branch `{branch}` from `{integration_tip}`. Territory: `stage1/cohere/lint/rules/{family}/{slug}/` only. The integrator owns dispatch/config and shared helper files. Use the common unit instructions, including cloud setup, plain commits, push without PR, five-line summary first.

1. Read root CLAUDE.md, lint README/REPORT/PERFORMANCE, rules/CLAUDE.md and PortingARule.md whole. Read `{go_sources}` and `{test_files}` whole, every listed shared helper, and `{previous_port_evidence}`. Do not re-port an implementation already present. State observations separately from conclusions.
2. Inventory contract: `{LOC}`, `{captured_invocations}` with `{test_status}`, `{fixer}`, `{suggestions}`, `{options_decoder}`, `{requires_options}`. Dependencies: `{direct_and_transitive_helpers}`. Released helper contracts: `{helper_commits_and_conformance_tests}`. Missing helper or AST shape: make the smallest valid probe that can distinguish Node from native; report its exact refusal or disagreement. Never substitute text heuristics for a binding or type question.
3. Implement the Go rule's judgments and spans on Adamic parser nodes. Preserve message IDs, rendered descriptions, UTF-16 source offsets, fix ranges, option defaults, invalid-option errors, and ordering. Shared helpers carry their own oracle tests. Suggestions are suggestions; never apply them as automatic fixes. Imports, comments, JSX, optional chains, malformed recovery and compiler options are included wherever the actual Go tests include them. State unsupported shapes explicitly rather than silently returning clean.
4. Type bridge requests: `{checker_questions}`. Require exact questions about types, symbols, declarations, options or project files, with error and unknown outcomes distinct. No half binder or local approximation of a checker. If the bridge cannot answer, report blocked with a reproducing case; syntax companions may land independently.
5. Capture the Go tests through an overlay without touching the submodule. Run Go cohere as the semantic oracle, then the same Adamic source on Node and sanitized native. Compare complete diagnostics, spans, fixes, suggestions and option cases; unique fixtures and harness calls are separate denominators. Also run pinned src/compiler and the repository manifest. Refuse an empty corpus, an inert instrument, or a wrong test filter. Use subject counters and seeded failing/passing controls when explaining a zero. Corpus aggregation must respect type-identity and project-configuration boundaries.
6. Run compiling mutants for each new load-bearing check: wrong anchor/span, dropped branch, ignored option, inverted helper answer, suggestion promoted to fix, or inaccurate bridge result as appropriate. Run the baseline under the identical filter first. Record which assertion catches each mutant; a compile failure or empty run does not count.
7. Save test output to files. Run touched packages and a filtered external oracle. Report covered shapes, exact counts and commands, every observed mismatch, every mutant, explicit omissions, setup timing/nproc and commit SHA. Commit only your pathspec and push. Return the local registration descriptor to the integrator; do not edit shared config read/modify/write concurrently.

## Example 1: no-debugger, a small syntax rule with a conditional fixer

Rule `no-debugger`, family core. Read `cohere/internal/lint/rules/core/no_debugger.go`, its register companion and `no_debugger_test.go`. The inventory records 59 Go lines and 30 harness invocations across six caller locations, including absent-node controls; the core family passed. The scanner branch already has an executable selector: this is a verification/completion example, not a new worker assignment.

Judgment: report a DebuggerStatement, not an identifier/string/comment containing `debugger`. Preserve the `unexpectedDebugger` message and automatic removal only when the statement belongs to a statement list. An unbraced if/loop/label body reports without a repair, because removal would leave invalid syntax. There are no options or suggestions. Use the shared report/fix adapter and UTF-16 range contract. Read `Context.RemoveNode`: a removal range must respect the actual Go contract. Require a seeded `debugger;` control to fire once and `const debuggerEnabled = true;` to stay clean, plus all Go fixture shapes. Mutants: replace the anchor with a different statement; shift the end offset; allow removal of an unbraced body. Go diagnostics and Node/native outputs must catch each independently.

## Example 2: no-warning-comments, comment collection and options

Rule `no-warning-comments`, family core. Read `no_warning_comments.go`, `no_warning_comments_register.go`, `no_warning_comments_test.go`, the custom `DecodeNoWarningCommentsOptions` and every dependency named in the inventory row. The inventory records 431 Go lines and 128 harness invocations across five caller locations; the core family passed. It has options, no fixer and no suggestions. The scanner branch already implements this rule, comments.ts and Unicode data; verify that implementation and lift only the helper contracts needed by new rules.

Options include terms, location and decoration. Preserve defaults, word boundaries, Unicode folding, decorations, comment order, directive exemptions, quoted rendered comment text and the exact report range. No automatic fixer or suggestion is expected. Land a shared comment collector, Unicode simple-fold/printability contract and strict option decoder before dispatching new consumers; the existing local collector is evidence to reuse, not proof of a general public API. Do not match raw `//` inside strings, regexes or templates as comments. Capture all option configurations separately from unique sources. Mutants: remove directive exemption, collapse a decoration range, corrupt one fold mapping, ignore a terms/location option. Compare full message text as well as counts. Explicitly test invalid decorations through the config decoder, not just through manually supplied option structs.

## Example 3: @typescript-eslint/no-unsafe-call, a checker rule

Rule `@typescript-eslint/no-unsafe-call`, family typescript. Read `no_unsafe_call.go` whole, its registration/test files, local `skipCalleeParentheses`, and `internal/lint/checking` helpers resolved in the inventory. The inventory records 284 Go lines and 44 harness invocations across two caller locations; the typescript family passed. It needs the bridge and has no options or fixes. Do not dispatch until these bridge questions are oracle-proven:

- What is the callee/tag's constrained type, including a generic constraint?
- Is that type any, intrinsic error, intrinsic void, or the global/default-library Function (possibly inherited), as opposed to a local Function alias?
- What call and construct signatures exist, and what is each call signature's return type?
- Is noImplicitThis enabled under the actual compiler options? What is the relevant this expression's constrained type?
- Which declarations belong to the default library, so builtin provenance is established?

Anchor CallExpression, NewExpression and TaggedTemplateExpression. Exclude dynamic import. A call/tag reports the unwrapped callee/tag; new reports the whole new expression while typing its callee. Preserve eight message IDs and the error-vs-any distinction. Any construct signature permits both call and construction; call permits any call signature, construction requires a non-void-returning call signature. Preserve that asymmetry. The Go file documents the harness's strict/noImplicitThis blind spot: add a separate configurable-program oracle for the false setting rather than claiming its existing fixture set proves that branch. Mutants: merge intrinsic error into any, confuse default-library Function with a local alias, treat void call signatures as constructible, ignore noImplicitThis, or report the callee span for new. Fixture tests and independent program controls must fail for the intended reason. Block explicitly if the bridge cannot answer these questions for `.a` source.
