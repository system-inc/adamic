# TypeScript-shim

Generated re-exports of TypeScript's Go internals, so cohere can reach them.

## Why this exists

The compiler keeps its real packages under its own `internal/`, which Go
enforces: nothing outside that module can import them. cohere needs
`ast.SkipParentheses`, `checker.Checker`, `tspath.NormalizePath` and a few
hundred other symbols, so `internal/types/tools/generate_shims` emits a thin package per
subsystem that re-exports them by `//go:linkname`.

Every file here says `// Code generated by internal/types/tools/generate_shims. DO NOT EDIT.`
and means it. Change the generator, not the output.

## The directory name and the import path are different things

The directory is named for its job: it ships the submodule's internals over
into the program. The packages inside it are imported under upstream's
namespace, not ours:

    github.com/microsoft/TypeScript/tsc/shim/ast

not `github.com/system-inc/cohere/TypeScript-shim/ast`. That import path is
what makes the `//go:linkname` references resolve, so it is the half that
cannot change. The directory is only the local target of the `replace`
directives in `go.mod`, which is why renaming it cost fifteen lines there and
three in the generator rather than touching the ~500 import sites.

An earlier version of this file argued for the bare name `shim` on the grounds
that renaming meant forking upstream's module layout. That conflated the two
halves: the layout being forked is the import path, and the directory name was
always free.
