Observations
Boolean array elements are untagged 8-byte adamic_value slots, with a bool member. They are not individually heap boxed. Reads produce a two-field adamic_maybe_boolean struct (present, boolean), not a heap union. There is no retain/release per boolean element read. The release of the array is outside the sieve loops. Array reads already inline adamic_array_at; they retain negative/NaN, upper-bound and fractional-index validation. Source-line costs for these individual predicates were not isolated by the non-debug profile, so no instruction number is assigned to a predicate or to the 8-byte representation itself.

Changes and correctness
primitiveArrayStore handles only Boolean, Number and MaybeNumber. It performs the existing adamic_array_at validation after operand evaluation; a valid slot gets the same adamic_value assignment, with no runtime reference branch because the element type proves it holds no reference. An invalid slot calls the existing array_set path for its exact message and exit code. Reference arrays retain the existing ownership path unchanged.
booleanLiteralEquality specializes MaybeBoolean ===/!== a right-hand boolean literal wrapped by MaybeOf. The literal is proven present. The other operand is evaluated once, its presence test remains, and equality is present && boolean == literal. Arbitrary optional operands keep the general equality path. No array access is assumed in bounds or defined, and no ! assertion behavior is changed.
The pinned test compares valid boolean, number, optional-number and heap-string stores with Node in release and ASan/UBSan builds. It covers true, false, missing, fractional and negative reads. A C ABI pin compares emitted invalid boolean stores with the existing runtime operation for -1, length, 0.5, NaN and infinity, including stdout/stderr/exit 70. Dropping the operand's presence test is caught by missing elements incorrectly comparing equal to false. Widening the scalar path to reference elements is caught by LeakSanitizer on an overwritten heap string made with repeat, not an immortal literal. Neither mutant is killed by a compiler warning.

Runtime boundary: proposal only, stop here
A one-byte boolean[] representation needs an explicit runtime array storage kind. Proposed API: a Boolean storage kind and constructor, with a typed bool buffer and byte-sized capacity/growth/copy operations; keep the existing adamic_value storage kind for numbers/references. Boolean reads must return value plus presence (or a bool-address helper), because the existing adamic_array_at pointer-to-adamic_value contract cannot safely point at a one-byte buffer. Boolean writes retain the current invalid-index diagnostic. Generic push/pop, slice/splice, fill, sort/reverse, join, search, visits, spread and destruction must dispatch by storage kind; array->references remains false for boolean storage. Emit direct bool-buffer reads/writes only when that kind is proven; update every emitter's generic element access to use the new runtime contract. noUncheckedIndexedAccess still distinguishes undefined from false. No per-element allocation is introduced. Representation width savings cannot be quantified by the current profile alone; measure a runtime-owned implementation before claiming its effect. No runtime storage or character/string code was edited.
Bounds elision also stops here: index <= limit by itself proves neither index < array.length nor integrality. A further emitter proof needs the fresh array's fill relation, no intervening length mutation or escaping alias, and the counter's integral range, including overflow/non-finite cases. Current bounds checks remain. The non-null assertion worker can preserve its own undefined check while a later range proof is developed independently.

W6 remains queued after these emitter items. Parse numbers in the parent field-store report refer to that fix; they have not been remeasured for this additional patch. No third-of-emitter-share claim is made.
