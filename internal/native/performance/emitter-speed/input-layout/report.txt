The premise about phantom layouts does not hold for this workload
Batch 8 parse.a imports readTextFile. run calls it for every source, and main calls it for the manifest; generated C contains adamic_read_text_file at lines 25731 and 30447 in the retained snapshot. Thus the input API's actual {kind,text} layout must remain. A conservative whole-program predicate necessarily returns true.
There are also real generated conflicts independent of input: Scanner text at slot0/kind at slot4; ParseNode kind at slot0/text at slot4; Edit text at slot3; saved scanner/parser states put kind at slot3. All observed generated offsets for both text and kind are {0,3,4}, before the runtime input text1/kind0 are considered. Deleting the input seeds cannot make either field globally uniform even without file reading. This report does not remove the existing class/shape safety checks or change layouts. Improving those scanner loads needs a separate proof about the receiver/layout, not omission of a reachable runtime layout.

General implementation
fields.go includes the input/directory seed group only if the fully lowered program contains ir.ReadTextFile, ir.WriteTextFile, ir.ReadDirectory or ir.FileStatus. programArguments and UTF-8 helpers produce no object layouts and do not enable this seed group. Other runtime layout groups remain conservatively included; regex programs still retain all checked field access. All class, spread, static/inherited field and object-literal conflict handling is unchanged.
programHasExpression in emit_speed.go uses the existing native walkExpressions traversal: Main plus every lowered function body, including nested expressions and statements. It counts even unused function/callback bodies and branches; no alias or call-graph reachability is guessed. This has the same conservative completed-program coverage as the frozen-guard audit. That unit stopped without implementing a freeze flag, so there was no implemented freeze predicate to share; the reusable helper shares the native walker and can serve future whole-program predicates. Lowering's private objectCanFreeze and the frozen guards are unchanged. Naming and temporary/cache counter mechanisms are untouched.
Audited the four native runtime entry points: input.c defines read/write text file; directory.c defines read directory/file status; the header declares them. No internal runtime caller of any of the four was found. Their generated callers correspond to the four IR expressions. If another runtime caller can create those layouts, this conservative predicate must account for that entry or retain unconditional seeding.
