Exact proposed boundary contract, pending agreement
1. Runtime owns a UTF-16 property-index read API, proposed adamic_string_index_unit(string,index) -> adamic_maybe_number. Present contains an integer code unit0..65535; absent corresponds exactly to string[index] === undefined. Negative, fractional, NaN, infinities and past-end indices are absent; -0 is index0. No substring string is created. Runtime may reuse its existing ASCII/index cache paths; no zero-allocation claim is made for lazy index/checkpoint construction. Preserve supplementary-pair high/low halves and lone-surrogate behavior over WTF-8.
A bare substitution of charCodeAt is UNSOUND: charCodeAt coerces NaN to0 and truncates fractional indices, whereas property indexing rejects them. Bounds/integer validation must remain unless the IR proves it; no such proof is asserted here. Implementing/changing that validation or character decoding is runtime's boundary item.
2. After agreeing that API, lowering can introduce a generic StringIndexUnit expression (string expression plus numeric index), represented as number|undefined. Its native emission snapshots/evaluates operands in JavaScript order, preserving the same source lifetime, null/TDZ/shape checks and effects as the original read, then calls the agreed runtime API. JavaScript backend uses the actual property read and, only when present, charCodeAt(0). Neither backend guesses an ASCII-only source.
3. For a proven single UTF-16-unit literal K, the pure expression (source[index] ?? '') === K can use unit.present && unit.number === codeUnit(K); !== is its exact negation. Equality with '' is !unit.present. Do not apply this rule to arbitrary strings or multi-unit literals. Snapshot the result once; preserve short-circuit behavior and each read's position relative to calls/writes. This removes only the intermediate string materialization at recognized consumers.
4. W6 reaches that pattern through Parser.peek, not a local direct expression at each comparison. A general interprocedural specialization is needed: only when the call target is uniquely proved and its body is precisely the checked property-read/empty-coalesce wrapper, use a specialized numeric-returning function with the same stack and field checks. Never recognize the source spelling Parser.peek, guess purity from a name, bypass virtual dispatch or inline away stack safety. Functions with additional effects/checks, unknown or multiple targets keep their string result. Existing function naming and counter mechanisms remain owned by their assigned worker.
5. Parser.string's character is also appended. Comparison specialization alone does not eliminate that allocation. A later representation could capture source/index/unit before this.index++ and materialize the exact old character only on a string consumer, or runtime could offer an append-UTF16-unit operation. Both require explicit ownership and surrogate-joining contracts with runtime. Do not reread source[this.index] after increment, append raw UTF-8 bytes for a code unit, or silently change retain/store/release order. Keep the present string path until that separate contract is agreed. No parser source rewrite or compiler exception for this service is proposed.
