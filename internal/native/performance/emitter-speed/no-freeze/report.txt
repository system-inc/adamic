Decision
Stop under the user's 2% cutoff. Dropping the 424 emitted public frozen conditions saves 1.9334% of instructions but yields no measured user-time improvement. Best of ten gets 0.8595% worse and simulated L1 instruction misses rise 0.1936%. No program-level IR flag or compiler/runtime optimization was implemented. Hardware cycles were not measured: the observation is no user-time saving, not proof that a hardware cycle count is unchanged. The experiment is scratch-only and unsafe on freezing programs; the production compiler still emits its guards.

Soundness audit: every caller and every way to set frozen
Audited 9e1fa18 (code equal to 2ad6ce8), origin/area/runtime 94a9c832bc773536cdf75904cbf811990c7e76aa, and current origin/main b6b1538. audit.json pins full resolved SHAs and search output.
1. User-lowering entry: internal/lower/object.go builtin recognizes intrinsic Object.<method> and dispatches to objectCall in internal/lower/library_object.go. Object.freeze on a present plain object becomes ir.ObjectCall{Method:"freeze", Returns:ir.Object}. Native internal/native/library_object.go:20 emits adamic_object_freeze(argument). This is the only generated C caller found in all three revisions.
2. Primitive Object.freeze(number/boolean/string/undefined) in library_object.go:37 lowers to the operand expression directly. It cannot freeze an adamic_object, so this form need not make the object-freeze fact true. Unsupported array/function/class freeze forms are refused rather than silently lowered without tracking.
3. Runtime callers of adamic_object_freeze: NONE. The function definition in runtime/library_object.c:26 and the header declaration are not callers. No internal constant freezing, template-object freezing, function-pointer aliases or alternate native freeze entry point was found.
4. The only write of true to object->frozen is adamic_object_freeze in library_object.c:27. Object allocation in object.c:11 and region allocation in region.c:65 set false. No static adamic_object aggregate initializer was found in the emitter or runtime. Object copies allocate a new object with frozen false rather than inheriting the source flag. Immutable string/number/boolean literals have other heap kinds; Object.isFrozen returning true for primitives does not set an object's frozen flag.
5. General tagged templates are NotYet in lower/library_string.go:363-364. Intrinsic String.raw templates lower to string constants/concatenation, not a cooked/raw template object with an internal freeze. Ordinary template expressions concatenate strings. Regex bytecode constants likewise do not freeze objects.
6. Object.assign checks writes, including runtime field loops, but does not freeze its target. Spread/reuse checks frozen status without setting it. They remain unchanged in this experiment.

objectCanFreeze in lower/library_object.go:190 recursively visits every expression/statement in Main and every Functions body, looking for ObjectCall.Method=="freeze". Its reflection walker traverses nested operands, arguments and statement bodies. Scanning every body conservatively includes aliases, closures, methods, callbacks and functions not called at runtime; it does not rely on an alias or reachability proof. Static/module initialization is executable Main or function body IR. There is no executable initializer stored elsewhere in Program.Classes. For the audited closed-world program/runtime, after lowering all modules and functions, this catches every generated caller that can set frozen. The runtime remains linked with an unused freeze implementation; link presence alone is not reachability from main. A future runtime caller, alternate freeze lowering or frozen aggregate initializer must make the fact true or retain the guard. Any implementation must compute the fact only after the complete lowered program is available. This report does not thread that fact, so it introduces no new reliance on it.
Stage 1 parser/scanner and batch 8 measurement sources have no Object.freeze call. The preserved guarded generated C has no adamic_object_freeze invocation. Stage1/cohere/typeaware/bound.ts contains the spelling in a string inventory, not an executed freeze call. Corpus fixture text containing freeze syntax is parsed input data, not executed by this native program.

profile.py and timing.py record exact commands and the local Valgrind/wait4 paths. Decompress profiles then use ../cache/summarize.py. The scratch deletion must never be applied to a program whose generated C calls freeze or whose runtime can freeze internally.
