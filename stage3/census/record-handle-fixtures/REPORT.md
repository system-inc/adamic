# Record handle fixtures: ny0c3gb

Base: `origin/main` at `9ed4c1db0b03d56b23d88345a9298a32379c1bbe`.

This report contains two distinct experiments. The first table concerns callable values stored in record fields; it does not answer whether a record itself can have a function receiver type. The [second table](#second-table-record-values-as-function-receivers) tests that corrected question.

The second experiment finds a cast-free road for all 10 kinds and all three function shapes: `Object.assign(h, sourceFunction)` returns the original record with a declared intersection type, which can then be assigned to a variable annotated with the plain function type. At its invocation site the receiver has that plain function type. Runtime identity is unchanged; it is still an object and calling or constructing it throws `TypeError`. The honest typeof-predicate road type-checks but takes its false branch for every record.

Receiver follow-up base: `6de78d4da0b1d4ba43d0d83ff38d3e760491c84e`.

## First experiment: callable field values

The field-value experiment has successful cast-free roads for every non-callable holding kind (1 to 4 and 6 to 10):

* `assign-result`: `Object.assign(h, { k: fn })` returns an intersection with a callable `k`. Reading that returned receiver and calling the bare-name local succeeds.
* `erased`: `const erased: {} = h; const receiver: MapLike<Fn> = erased;` needs no cast. Store through `receiver`, read its `k` into a local, then call that local.

Both roads print `called` on Node v24. The original holding type is not the read receiver in these two cases. At the read relation site the receiver is respectively `Holding & { k: Fn }` or `MapLike<Fn>`. These are successes in the field-value experiment only, not function-receiver counterexamples. They do not establish that a read through the unchanged original holding type admits a function.

`assign-h` and `unknown-helper` successfully mutate storage without a cast, but the subsequent read as `Fn` through the original holding type fails. Direct writes and spreads fail. A single `as MapLike<Fn>` is rejected for the non-callable kinds; going through `unknown` permits the cast and the call, explicitly requiring casts.

## Scope and source fidelity

Each fixture is self-contained and imports nothing. Non-control cases use the listed receiver shape `(path: string) => string`. Kind 4 is checked inside an unconstrained generic function, then invoked with `string`. Every holding starts with a fresh `{}`. The spread road creates another literal held by the same holding type. Reads use `.k`, guard only against `undefined` to respect `noUncheckedIndexedAccess`, bind `const read: Fn`, and call the bare name `read`. There are no non-null assertions or suppressed diagnostics.

Definitions come from [TypeScript v6.0.3 types.ts](https://github.com/microsoft/TypeScript/blob/v6.0.3/src/compiler/types.ts) and [core.ts](https://github.com/microsoft/TypeScript/blob/v6.0.3/src/compiler/core.ts). `CompilerOptionsValue`, `PluginImport`, `ProjectReference`, flag enums and `InternalSymbolName` are copied. `CompilerOptions` retains the exact index signature and representative boolean, string, array, map and config-file members. `Type` and `Symbol` retain every required member, including internal members, and omit optional members as requested. `TypeId` and `SymbolId` are numbers, as in the source. Dependency leaves are deliberately reduced: `TypeChecker` is opaque `object`; `TsConfigSourceFile` retains required numeric `kind`, `pos`, `end`. No fixture constructs those dependency leaves. Their omitted structure cannot make a property-free function satisfy the required fields of `Type`, `Symbol`, or a source file.

The specified `extend<T>(MapLike<T | undefined>, MapLike<T | undefined>)` is used verbatim as the requested holding signature, called as `extend<() => string>`. Upstream v6.0.3 core.ts actually declares `extend<T1, T2>(first: T1, second: T2): T1 & T2`; this fixture follows the task's explicitly supplied variant. The loop body copies second then first. The control uses `MapLike<() => string>`.
