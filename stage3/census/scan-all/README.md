# scan-all: refusal-scan continuation census

One invocation is **one root import-closure run**. In the gate, the anchor test and all eight continuation controls run; the products phase builds their two binaries ahead. This records refusal-scan stops only, plus the first declaration, body or tail stop it reaches, and is blind past that first stop. **A zero for a body-phase or tail rule is never a pass.** It is not production's full wall list. Preflight and registry validators can themselves return their first error; this does not enumerate all errors inside a validator.

This tooling copies main's production lowering into a build overlay. It continues only the refusal scan, then uses the unchanged production declaration/body/tail abort behavior. There are no archived Language or Memory rule files, no snapshots, placeholder bodies, independent-unit union or compiler acceptance path. Both public lowering APIs return nil IR and a measurement-only error. The measurement API returns observations and counts only. Each process accepts exactly one root and runs once; its globals are not a concurrent API.

`make_overlay.py` writes only outside the checkout. `--check` reads the sources in Python and checks the anchors the overlay depends on, with no whole-file hashes and no Go subprocess. It checks all eight `LOWER_REWRITES` anchors exactly once, requires at least one pipeline error-boundary regex match, and checks each matched site exactly once. In `refusals.go`, it checks the original `refuse` signature, its pragma loop, both visitor signatures, the registry rule call and each matched module preflight. Checks are scoped to `refuse`, so the separate `refuseNode` walker is not mistaken for a duplicate. An unrelated comment or other edit outside these anchors does not invalidate the check.

Some anchors exist only **after refusalrewrite runs**: the `latentRefuse` clone, the named `latentStop` visitor signatures, each visitor's `latentRecord` defer and `latentFullEnabled()` exclusion block, and the clone's label-insertion sites. The instrumented product recipe runs the Go AST rewriter outside test units and refuses on missing or duplicate generated anchors, naming them. The anchor test remains Python-only; the instrumented product recipe validates the generated anchors before building the scan binary.

`TestScanAllMainAnchorsMatchExactly` checks main's current source anchors. `verify.sh` also runs that unchanged named test on isolated scratch copies: removed and duplicated lower/refusal anchors must turn it red and name the anchor; an empty pipeline-site match must turn it red; an unrelated comment added to `lower.go` must keep it green. A trap on Go subprocesses proves the check itself never runs Go. No checkout source is mutated for these proofs. Preparation failures are reported as a boundary without fabricating a declaration/body/tail observation. The underlying first pipeline stop is captured before production's deferred host-write diagnosis can replace it; it is counted once. The report does not treat the substituted diagnosis as another completed pass.

Every observation carries a `Kind`: `scan stop` or `first declaration/body/tail stop`, plus rule, site and words. Registry labels name the actual rule. Non-registry labels distinguish checking pragmas, suppression directives, the argument-contract walker and each module preflight. Production retries can repeat observations; event counts retain those repetitions. Events and distinct `(rule, site, words)` triples are different measures. The summary runner groups files from the sites, never from a claimed root count. `Completed` describes measurement traversal only, not compilation acceptance.

## Reproduction

Use a detached worktree of main, initialize recursive submodules, and install `stage3/api` with `npm ci`. Set `ADAMIC_TYPESCRIPT_SOURCE` to TypeScript v6.0.3, commit `050880ce59e30b356b686bd3144efe24f875ebc8`. Put `GOTMPDIR`, `TMPDIR`, `GOCACHE`, `ADAMIC_BUILD_CACHE_DIR` and `SCAN_ALL_SCRATCH` in scratch outside the checkout. Use the repository's Go 1.27.1 toolchain.

```sh
bash stage3/census/scan-all/verify.sh
# The report command needs an exported scan binary; find the probe path in the product test log.
stage3/apply.sh --build-product "$SCAN_ALL_SCRATCH/adapted"
python3 stage3/census/scan-all/report.py "$SCAN_ALL_BINARY" \
  "$SCAN_ALL_SCRATCH/adapted/src/compiler/sys.ts" "$SCAN_ALL_SCRATCH/sys.md"
```

`TestProduct_ScanAllInstrumentedProbe` declares `scan-all-instrumented`: its recipe runs `make_overlay.py` (including `go run` of refusalrewrite), then `go build -overlay`. `TestProduct_ScanAllProductionProbe` declares `scan-all-production`: its recipe overlays only the plain `production.go.txt` entry point and builds against unchanged production lowering. Both use `buildcache.Product`, produce `probe`, and discard their temporary overlay files. Both builds use `-trimpath`, `-ldflags=-buildid=` and `-buildvcs=false`.

Their keys use `GoInputs` on `internal/lower` for the full transitive Go source closure, module/workspace pins, Go build settings and toolchain reports. This includes all lowering sources, especially the original `lower.go` and `refusals.go` that generation reads before replacing them. The declared files additionally name the recipe, `make_overlay.py`, `main.go.txt`, `scout.go.txt`, `production.go.txt`, and the whole `stage3/census/latent/refusalrewrite` directory (including its command); Python's version joins the tool reports. The two product names distinguish the recipes. These declared files key local fallback builds. Under traced settlement, the actual source reads and the linked test recipe key each product: Python reads the generator and templates, generation reads the original lowering files, Go reads the rewriter sources and the binary's transitive sources. Generated scratch paths are build outputs, not missing source inputs. The production binary has no lowering overlay; its main template and production source reads enter its settled key directly.

The eight `TestScanAll{Count,Rest,Record,Cycle}{Stop,Clean}AfterEarlierScanStop` tests each call `t.Parallel()`, fetch both products through the same helper as their declarations, and run `controls.py` with a 55 s process-group deadline. There are no skips and no build commands in the controls. Each control first checks its pragma-free fixture with the plain production probe, then restores the earlier checking pragma and requires the later target or clean completion from the scan probe. Positive controls also require the exact pipeline boundary. Both public no-IR guards run on every scan invocation.

`verify.sh` first runs the product declarations, then runs the Go controls in the caller's cache mode. It preserves that mode for every mutant too. A sealed box's untraced declarations create local products; forcing read mode afterward would reject them because they have no traced read sets. In the gate, inherit `ADAMIC_BUILD_CACHE=read` with already-settled products to prove fetching only. A `hit` log prints the full product key; a `missing` log prints its name key, so those two hashes are not evidence that a name key moved. It also covers what the normal tests do not: eight separate named-test first-error mutant runs, and the isolated source-anchor mutation proofs described above. The mutant is **runtime** `SCAN_ALL_MUTANT_FIRST_ERROR=1`, read by the already-built instrumented binary; it needs no product rebuild. Each named control must turn red with `continuation-target` (stop fixtures) or `continuation-completion` (clean twins). A build, load, timeout or other failure does not count as a killed mutant. The source-anchor proof still copies only the standalone anchor test, never the product declarations or controls.

## Controls

The control rule locations below refer to main `89614cc0f9d6aa7b7fe96b56c5c6c1c3eace9825`. Every fixture begins with the earlier `@ts-check` scan stop (`internal/lower/refusals.go:53`). Each pair changes the relevant input; names describe the later production stop, not an all-stop census result.

- `count-stop` and `count-clean`: argument-count observation through a bound function; `checkBoundArguments`, `internal/lower/function_bind.go:361`, diagnosis at line 377. The twin returns its parameter without reading `arguments`.
- `rest-stop` and `rest-clean`: direct rest-parameter bind; the production body-lowering check in `functionBind`, `internal/lower/function_bind.go:54`. Main rejects this before `checkBoundArguments`, so this pair claims a first body stop, not a tail result. The twin has no rest parameter.
- `record-stop` and `record-clean`: record written directly into a graph slot; `findCycles` / `graphTypes` / `noteRecordSlot`, `internal/lower/graph_records.go:16`. The twin uses arrays of nodes rather than a record.
- `cycle-stop` and `cycle-clean`: record held inside an array written into a cyclic graph holder; the same production record rule, whose `holdsRecordSeen` follows array elements (`internal/lower/graph_records.go:54`). The twin uses node arrays. These share the record validator but exercise different written value types.

No `declaresBeyond` control is claimed: that rule is absent from this main. The eight controls target rules main actually has. Each has its own first-error mutant run, which must turn that control red; clean twins prove continuation by completion, rather than by inventing a clean rule event.

## Isolation and evidence

Nothing under `internal/lower` is edited. The only generated replacements are copies of `lower.go`, `refusals.go`, the measurement helper and tool entry point. No gate consumes the report. `verify.sh` adds opt-in mutation proofs to the always-running Go controls; these report streams are not compiler products or acceptance receipts. `examples/` contains summary tables only, with warnings repeated before every table. Raw streams stay outside the repository. Resource measurements cover loading/checking and lowering in the child, excluding adaptation and builds; peak RSS is Linux's child maximum in KiB.
