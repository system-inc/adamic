## Inventory and scoping plan

`R` means recorded lowering sites/produced IR (possibly with checker queries on their AST identities). `G` means a graph/fixed point whose production universe is all lowered functions/classes, even if constructed solely from IR. `S` means whole-source/module facts. A G pass can execute on a partial IR, but its answer can change when omitted bodies arrive. “Run” below means run as an explicitly **scoped observation**, never count it as whole-program coverage. “Report omitted” means report that status on each unit. “Whole” means the production question cannot be answered meaningfully by independently lowering that unit.

All scoped passes must retain original numeric IDs and the signature placeholders they reference. Do not slice/compact `Functions` or `Locals`: calls, sites, views and dispatch tables index them. Filter **roots and site ownership**, not IDs. Include every helper/concrete instantiation/nested body produced while lowering the unit, not just its named function. A fresh first-error lowering already isolates state. For a shared registration base, take `latentSnapshot` **before the unit**, run body and tail on that copy, then discard the entire copy on success, error or panic. Do not carry tail-derived registries between independent units. Named functions/classes are pre-registered, so the produced bodies are not necessarily an appended suffix: track touched existing IDs as well as newly created helpers and sites. The probe retains the whole fresh registration skeleton, including empty signature stubs, and walks its produced bodies; it does not synthesize the missing callee bodies. Independent products cannot be concatenated into one program without resolving their local/helper ID collisions and graph holes.

### Tail-adjacent work and delegated passes that must not disappear

`findCycles` includes, in order, generated async cycle-identity validation; AST made/shape/use/library-iterator census; instantiated checker-type uses; `cycleFinder.graphTypes` (`graph_types.go:89`); `jsonReferenceReach` (`library_json_stringify.go:335`); then, in discovery, `resolveCountTypes` + `selectProgramMembership` + `checkLazyViewReads`. Ordinary lowering instead does `resolveCountTypes`, `nodeProcessStorageABI`, `nodeFSDirectoryClosureABI`, and `checkLazyViewReads`. The latter calls `certifyUntaggedCallableProducers`, `completeUntaggedRecursiveContracts`, `checkViewArrays`, and the lazy-view read/storage proofs (`view_lazy.go:131`). `resolveCountTypes` also calls `resolveStructuralMethodThunks`, replaces FunctionTypeTargets, propagates forwarded ReadsArguments to a fixed point, calls PrepareArgumentSlots, adds argument-count locals and equalizes virtual signatures. Thus a later pass can be callable yet semantically unready when findCycles is omitted. These are not “just find cycles”: omitting them also omits callable/recursive contract certification, checked-array refusals, Node storage ABI checks and count-type metadata. Their source/graph universes and plan mutation make the aggregate **Whole**. A later implementation may split independently meaningful site checks out, but must audit each helper's inputs before claiming it ran the original pass.

Outside the tail, `lowerCheckedWithCycleTypes` (`lower.go:91–108`) reruns **the entire lowering** with an every-element key when the first key missed an element contract, then refuses relation overflow as `NotYet`. The census's per-unit `latentCheckUnitRelation`/final relation ledger is a different observer and must remain visible in any comparison. `lowerWithElementKey`'s deferred `hostMemberPending` (`lower.go:112–114`, `host_member_write.go:109`) can replace an earlier error with the first unjudged deferred host-write stop. A faithful production-tail report should retain both raw pass failure and this effective error. The prototype reports raw pass errors; it is not a replacement for this wrapper.

### State isolation details

The unit checkpoint must own result Main/Functions/Locals/Classes, MethodTargets/FunctionTypeTargets, checked fields/contracts/origins, generated layouts and source metadata; forwarders; accessor/class/instance registries and getter declarations/holders; ToPrimitive ID/string intern table; iterable/generator arguments/views/tries; async/string/write/move sites and stored payload failures; optional/record-guarded/host writes and hostMemberJudged; whole-object copies, narrowed/view facts, overload result witnesses/check-call maps, closure records; graph allocation IDs and all derived frame/exception/borrow/counter/readiness/Program flags. The generated state copier copies lowering-owned mutable descendants; checker and AST identities remain shared.

`statecopy/main.go:43–48` makes Program.methodTables a **privateEmpty** cache, argumentFacts **privateNil** (backend only), BoundaryStringTable.indexes privateEmpty and GeneratedType.identity immutable/shared. `full.go.txt:60–173` enforces these policies in reflective IR copying. Running more passes will populate caches formerly empty: do not copy a stale method-table cache across a rewrite, and do not let an ownership/backend analysis populate an unsupported private field and silently lose it. Keep timing/findings/run-owned witness streams outside the snapshots, as the existing census does. Current first-error mode creates fresh lowering per unit, so disposal is safer than restoring fields piecemeal.

## Scratch measurement method

`prototype.py` extends the stock **entry** overlay, with no backend and with ordinary Load/Lower still disabled. `--stock` retains the stock body-lowering path; both variants add ordinal range selection and the explicit optional scan switch. The prototype retains the unit's statement IR as Main (stock throws it away), stops before the tail if body lowering or `unlowerable` fails, and invokes the 26 exploratory scoped operations in production order. `findCycles`, Program-region gate, plan application and ownership query are deliberately not invoked. It records raw pass errors, not the deferred hostMemberPending override. It also supplies `entry` and a unit Source location, which stock's fresh lowering leaves unset. `passes-before-entry.go.txt` is the earlier pilot that exposed the missing-entry panic; `passes.go.txt` is the corrected measurement code.

`run-chunk.py` starts exactly one census child, limits it to 1,700 seconds, records its own child return code (including negative signal status), and propagates that exit/signal. A timeout terminates the child's process group and records the resulting child code separately from deadline expiration. Exit 0 alone is not success: the driver can write a checker-blocked header and exit 0. A complete bounded entry observation must have a measurement header, all file rows, and relation trailer; final unit coverage additionally requires a disjoint range union covering the independent manifest. `LWP_SKIP_SCAN=1` explicitly omits the independent whole-file refusal scan in both sides of the final unit-only experiment. It does **not** skip `latentDeferredUnit` or dependency deferred-stop probes. These outputs are not a replacement for the stock syntax/contract-finding census. Source scan findings can suppress a deferred stop when their owner coincides with a unit; omitting the scan is therefore a declared scope limitation, not a claim of byte-identical stock findings. The checker.ts pin starts with an import, so its function units do not share the scan owner. Two initial scan-enabled pilots were deliberately terminated during the remaining whole-file scans after their selected body attempts ended; their signal exits and partial streams are retained and excluded from final totals.

Unit selection is a half-open ordinal range in the driver's actual source traversal. Units skipped for generics/checker policy are still in that ordinal universe. Refusal scans remain whole-file and may be repeated across chunks; deduplicate those findings, never sum repeated scans as new blockers. `manifest.cjs` independently counts the resolved reach with stock TypeScript 6.0.3; its sorted source list is not used as traversal order.

Pass wall time is `time.Now`/`time.Since`, the **same monotonic clock as** `stage3/census/latent/timing/timing.go:40–49`. The timer includes its entry getrusage probe and wrapper overhead (not calibrated out), and ends before exit sampling and JSON logging; total unit time includes that instrumentation. Timings are sums over actual invocations, including errors and panics. First-error censoring means later passes have fewer opportunities; zero invocations is **not measured zero cost**. These are this box's observed costs, not a calibrated prediction of another meter host. Runs can overlap a paired stock run or parent adaptation preparation; wall differences between processes are not isolated causal estimates.

Memory columns are Linux `getrusage(RUSAGE_SELF).Maxrss`, KiB, sampled on each pass's entry and exit. “Peak” is the **process high-water mark observed at that pass**, including loader/earlier-unit memory. “Growth” is the sum of high-water increases **during that pass**. It is not a sum of per-pass resident sets or proof that the pass allocated nothing when growth is zero. Overall process peak comes from RUSAGE_CHILDREN in the one-child wrapper. Peaks cannot be added. An isolated incremental peak attributable to each pass would require fresh-prefix runs for every pass and chunk; that quantity is **not measured** here. It would require separate prefix sweeps (up to 26 operations across three chunks) under a settled body/graph universe. That calibration is stopped at the failed positive-pin/completeness gate; the current partial universe would not establish the intended integration cost. No fabricated zero is supplied for it.

The minimal detector fixture is evidence of both usefulness and limitations. Stock accepts all three unit attempts without findings. The initial prototype records a nil-entry panic at checkPromiseConsumption; setting entry removes it. The scoped iterable consumer has no caller in its IR, so checkIterableViews reports an unproven origin. The separate generator-call unit produces a checkGeneratorRoads invariant error because its signature-only callee metadata is incomplete. These are partial-universe observations, not evidence that the complete fixture is a newly broken language program.

## Concrete implementation plan for Compiler

1. Add a separate per-unit pass ledger before changing the meter's numeric claim. Each pass needs `executed_scoped`, `not_reached_lowering_stop`, `not_reached_earlier_pass_stop`, `not_run_whole_program`, `not_run_option_disabled`, or `panic`, plus scope/completeness and effective/raw reasons. A unit with any omitted required pass must not be presented as successful whole-program lowering.
2. Preserve Main, install entry/source, collect body-produced function/site ownership, and finalize the independent R checks on a disposable lowering snapshot. Retain stable IDs and include produced helpers/instantiations. Never copy a post-finalization state back into the registration base. Keep new IR mutations covered by statecopy's fail-closed field policy.
3. Treat the G checks as partial diagnostics until their external dependencies are supplied. Track `signature_stub`, `lowered_body` and `generated_helper` provenance explicitly; an empty Body can also be a legitimate empty function, so length alone is insufficient. Registering a sibling signature is insufficient: a read count, argument-use flag, getter effect or throw bit cannot be inferred from an empty body. In particular, do not turn the fixture's missing producer/callee into a production regression. Either mark the pass incomplete or construct a demand-closed body universe, recording every hole.
4. Cache only proven S facts, such as the library spread candidate type set, over the complete entry source graph. Do not “scope” findCycles by passing only one module. Discovery/plan/ownership remain a separate complete-program measurement with an explicit blocked status when lowering fails first.
5. Require a pin whose **unit body actually reaches the tail**. Also retain the five checker source sites as negative coverage witnesses: neither source presence nor a checker-clean root proves they were lowered. A nested-unit/statement-site experiment is a separate universe and must be labeled and baselined separately from today's first-error top-level census.
6. Publish “no observed lowering regressions” only with an unchanged coverage vector and its omissions. Publish whole-tail acceptance only when all required passes actually ran over a complete universe. Gate implementation on a local post-body refusal pin, a missing-callee/empty-signature pin, a Main-retention pin, state rollback/cache isolation, and a wrapper child-failure/timeout test. The scratch fixture already demonstrates why the missing-callee and Main cases matter.

### Panics and per-unit misbehavior

The final main experiment is summarized above; no initial pilot is silently included in it. The small fixture additionally exposes:

* **checkPromiseConsumption:** the pre-entry-fix pilot panics at probe.ts:1:1 with `runtime error: invalid memory address or nil pointer dereference`. It unconditionally reads `l.entry.AsNode()`, even with no async work. Initializing entry removes it. Both raw versions are retained under `evidence/fixture/`.
* **checkGeneratorRoads:** the generator-call fixture unit returns `lower: compiler bug: 1 generator values where only 0 are a consuming loop's or a dropped call's`. The unit has signature-only producer/consumer metadata. This is a census-scoping invariant error, not a demonstrated compiler bug in the complete source program.

* **checkBoundArguments / later CFG checks:** calling them without findCycles' resolveCountTypes leaves function-type targets and forwarded argument-count facts incomplete. A clean return is not evidence that the original pass question was answered. Their recommendations remain the inventory's omission/whole-program categories.
