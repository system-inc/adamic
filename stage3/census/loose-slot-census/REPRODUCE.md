# Reproduction notes

The scripts archive the exact `/workspace/loose-slot-scratch` layout used for this measurement. Change that prefix throughout the scripts for a different scratch directory. Do not reuse an existing adapted tree: apply intentionally refuses replacement.

1. Create a fresh detached worktree for main `fe5a1a54f045e9bce4e5aa32ca74885a317fbebd` and another for head `7e8cfaafb74a61f82f1610a4b738157b9918343d`. Run `git submodule update --init --recursive --depth 1` in each. Copy this census directory into the head scratch worktree. Only the measurement directory is needed; no production lower files are modified.
2. Clone TypeScript v6.0.3 and confirm full SHA `050880ce59e30b356b686bd3144efe24f875ebc8`. Set `ADAMIC_TYPESCRIPT_SOURCE` to that checkout. Install each worktree's locked `stage3/api` dependencies with `npm ci`, then run its `stage3/apply.sh` to a distinct `adapted-main` or `adapted-head` directory. `finish_inputs.py` checks successful apply completion and all 79 source hashes.
3. Use Go 1.27.1. Set GOTMPDIR and TMPDIR to a scratch `tmp` directory, GOCACHE to scratch `gocache`, ADAMIC_BUILD_CACHE_DIR to scratch `cache`, CENSUS_MODULE_FORMAT to `CommonJSBundle`, GOMEMLIMIT to `10GiB`, and PYTHONDONTWRITEBYTECODE to `1`. ProgramRegion and OwnershipQuery are off in these measurements.
4. Run `build_drivers.py`, which creates each one-root driver overlay and builds each SHA's unchanged production lowering. Build the latent overlay with `stage3/census/latent/make_overlay.py`, then `go build -overlay OVERLAY/overlay.json -o SCRATCH/latent ./stage3/census/latent/tool` from the head worktree. Run `build_type.py` to build the separate type-level instrument, and `build_type_mutant.py` for the private head-reach mutant. The exact binary hashes and probe-source hash used here are archived.
5. Run `controls.py` and `extra_controls.py`. They assert production arrays stops at 48:1, the completed latent control has zero findings without checker rejection, the type probe sees 48:1, and its mutant reads zero with unchanged gathering. k17/k18 must match production's exact sites.
6. Run `groups.py` on a new measurement branch. It runs up to two independent children at once, at most ten root indices per group, and commits and pushes each completed group. Set its checkpoint destination to the branch intended for the rerun; never force a push. Existing successful receipts are resumed, not silently rerun.
7. Run the type binary once over `adapted-head/src/compiler`, wrapped by `measure.py`; run the separate `type-count-mutant` binary with `LOOSE_MUTANT_DISABLED=0` for the whole-program mutant. The collector must remain active. Exact command arguments are in `evidence/type-whole.time.json` and `evidence/type-whole-mutant.time.json`.
8. After all roots complete, run `progress.py`, `analyze.py`, and `validate.py`. `SITES.md` quotes every observed positive location. The script intentionally labels the source reconstruction partial: the exhaustive production site count is UNKNOWN.

Every `.time.json` is a per-child `wait4` receipt: wall seconds and peak RSS in KiB. Summed child wall times overlap when children run concurrently. Setup, dependency installation, adaptation and cold build are excluded from those measurement times.
