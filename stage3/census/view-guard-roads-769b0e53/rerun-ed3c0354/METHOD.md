# Method and limits

The compiler target is ed3c0354e2d3f97663778e91aac7f100a47b4e18. The base is 16429a30. The parent streams, source-manifest hashes, adapted sources, parent apply.sh, pinned TypeScript 6.0.3 source, and dependency gitlink are reused from the archived census. The head compiler is built from its own checkout. provenance.json records the immutable evidence hashes. All 747 adapted source-file hashes were checked before the run.

The scratch overlay retains the archived meter's unit-end hook and the same real viewPairGuard invocation on each recorded view, with a fresh cycleFinder and an empty where map. It snapshots the unit's lowering state and presents one recorded view at a time. The unit's viewSources, checker, AST, local type state, and normal lowering-owned caches are the inputs. No graphTypes or findCycles call is made. No seen types, graph membership, shapes, graph result, static globals, or whole-program type universe is manufactured. Lazy fields and relation caches are populated by the real guard from this snapshot, as in the archived seam. GuardRefusal records are separate from the normal census stream. Each view produces at most its first real failure path; independent views are all examined.

The current observer recognizes the new real path label `a split arm` as the union-arm road. After a real refusal, the observer calls the real viewPairFailure to extract its path, as before, then annotates its root and every path pair. The annotations ask Checker_isTypeIdenticalTo and compare the normalized type pointers. They also describe literal-only common fields using the same criterion as this head's viewPairDisjoint, including undefined and null and pointer equality for shared literal values. These annotations do not decide guard acceptance. Diagnostic failure is recorded inside the refusal and checked by analyze.py, rather than hiding the refusal as a probe failure. The exact overlay sources, including the supplemental helper, are preserved with .go.txt names.

The complete extended observer source is byte-identical on both sides, and both compilers were built with it. Both real identity fixtures produce zero refusals, and both forced-refusal controls produce one refusal with diagnostics. The supplemental annotations are post-refusal only. The cached parent has zero refusals, so they would not execute there. Reusing that stream avoids a redundant parent run without losing any diagnostic data. The forced-refusal identity fixture control confirms that the current observer emits a record and executes its annotations. The real identity fixture and mutant normal streams are compared with the cached parent fixture.

analyze.py checks exact serialized ordinary finding arrays and all non-telemetry stream bytes against the cached seam-free baseline. It also verifies that only checker-cache-size telemetry may differ in the excluded relation_report record, that every unit's view count equals the parent's, and that no probe or diagnostic errors occurred. Thus guard observation must not change a unit's ordinary outcome. Separate guard-only streams are paired by the existing stage3/census/pair tool, preserving raw source offsets and distinct TypeScript access-chain reads. Exact finding comparison with the earlier 289 includes source identity, kind, reason and source text. A separate comparison by view location and source/target types detects a view whose first reason changed. The earlier 114 units are intersected with current refusal owners, independently of changed reasons.

Road totals count the first widened road along each real failure path; complete paths and all road labels remain in the records. The base pair check is retained as a separate bucket. Actual `a split arm` steps identify crossings the real guard splits despite no disjoint literal-only common field. Checker-identical but pointer-distinct pairs are listed at the root and at nested steps, so a nested cost is not missed.

This is a census of recorded unit-local views and latent guard refusals. It does not model whole-program graph membership, and a guard-stopped unit here is not evidence that the production tsc entry program reaches graphTypes or stops there. The ordinary first-error result is reported separately. First-error mode stops normal unit lowering at its first ordinary finding, so views after that point are absent. Full mode is conditional on new first-error findings and is reported separately after the first-error result has been announced.
