## Count definition

One row per exact `Refused.What` reason text, including its type arguments and field names. No collapsing different type relations into a shared rule code. Counts deduplicate `(kind, where, reason, text)` and include only `kind=Refused`, `phase=refusal_scan`, `unit=the selected body`. Nested functions are included. The separate first-error lowering finding is excluded. CSV retains one row per distinct finding, exact reason and diagnostic text, and its body attribution. Paths and line numbers are in the adapted `src/compiler` tree, not pristine upstream. Two examples are distinct file:line sites when available; singleton rows explicitly have no second site.

The production refusal walk can report only one reason at a given AST node before descending. The latent clone continues to every child exactly once after recording it. Thus this counts every refusal **observed by that visitor** throughout each requested body, not every hypothetical check masked at the same node, nor every blocker an eventual complete lowering might discover.

Dispositions are recommendations, not semantic proofs. Adaptation means retain the existing soundness/design rule and repair source contracts or syntax. Compiler lesson means extend a proof or correct a conservative rejection before lowering; it never means silently omit a check. In particular, checker-rejected `never` and `never[]` observations require a checker-clean witness before implementation. Predicate recognition limitations are lessons only where the missing proof is a supported control-flow/check shape; an unproven annotation remains an adaptation.
