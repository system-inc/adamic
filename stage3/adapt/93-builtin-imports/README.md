# 93: builtin namespace imports

Task #he8tysb, head 1. The independent base is main
7b9c0fe7e52cfe9cdeb774107389bd6870f41423. Upstream is TypeScript 6.0.3,
050880ce59e30b356b686bd3144efe24f875ebc8.

This is a JavaScript-changing adaptation, as decided by Adamic. In
src/compiler/sys.ts, getNodeSystem's fs, path and os requires become references
to three top-level namespace imports from node:fs, node:path and node:os.
The names adamicNodeFs93, adamicNodePath93 and adamicNodeOs93 are absent from
the entire input AST; the adapter checks that before planning their imports.
_fs and _path keep their original typeof import annotations. _os is untyped
on the fully numbered main input, and stays untyped.

The CommonJS compiler loads these three builtins eagerly at module evaluation
instead of requiring them inside getNodeSystem. That timing change is intentional.
Crypto, source-map-support, the plugin require, inspector, __filename and
__dirname are not changed. No other source file changes.

## Built compiler witness

proofs/built-witness.cjs runs each real built/local/tsc.js on the same small
strict project and compares stdout, stderr, exit status, emitted JavaScript
and emitted declarations byte for byte. A separate node -e process intercepts
Module._load while requiring each built/local/typescript.js. Main's three
bare builtin loads have getNodeSystem on their stacks; with 93, the three
builtin loads occur during module evaluation without getNodeSystem on their
stacks. Upstream esbuild normalizes the node: import specifiers to bare builtin
requires in the CommonJS bundle; the source imports retain node:. The
observation records the real stacks and Node version, then restores
the loader. It neither rewrites nor mocks the built compiler.
