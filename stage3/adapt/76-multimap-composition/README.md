# MultiMap composition

Implements @system_adamic's step 19 ruling #pvvzhmy as a tracked stage 3 adaptation under #pcwk8fh. The adapter replaces the reviewed core.ts factory and its two helpers with a class owning an ordinary Map and explicit-receiver helpers. The MultiMap interface and exported factory signature remain the same. Expando writes are absent. The source hash guard rejects drift; applying the adapter again checks the exact replacement and writes nothing. The measured row in stage3/patch-set.md is one file, 27 added lines, 11 removed lines.

The class delegates get, has, set, delete, clear, size, entries, keys, values, iteration and the string tag. set returns the composed receiver. forEach passes that receiver as its third argument and binds the requested thisArg. Collection iteration remains lazy and follows the underlying Map's mutation behavior. Composition changes instanceof Map and reflection on own fields; the sanctioned representation is not a native Map expando. This adapter preserves the delegated collection API, not arbitrary native-brand reflection.

replacement.a is the replacement fragment in core.ts, where MultiMap and unorderedRemoveItem are already declared. stage3/map-keys/multimap.a is the native reduced composition with explicit receiver helpers, held by scout_multimap_composition.a. They are different scopes: the complete class remains native NotYet for its computed string-tag accessor. The new probe discovered and fixes an accessor-name prepass panic so this dependency is reported loudly. No complete native factory or tsc compilation is claimed.

verify_multimap.cjs extracts the upstream declarations from the pinned adapted tree and compares the reduced helpers and actual adapted factory against them in Node. It exercises removal order, duplicate values, absent removal, deletion of empty buckets, NaN strict equality, object identity, optional values, receiver identity, bound forEach callbacks and live iterators. Strict checking of the extracted composed declarations reports no errors, and emitted declarations match the original. No API sanction-file change is required by this measured declaration comparison. The empty-bucket source mutant differs from upstream Node; the native empty-bucket mutant runs sanitizer/leak clean and differs from source Node. A generic undefined-check mutant panics in both generated backends; Node catches the wrong narrowing. The adapter's source-drift mutant also fails.

The reduced fixture passes source Node in both backends, sanitizer and leak accounting, with 33 allocations and 33 frees. Frozen census roots retired by this piece: zero. The generic census units and complete wrapper remain blocked; no hidden-byte recovery is inferred.
