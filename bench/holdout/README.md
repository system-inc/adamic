# The speed holdout

Programs nobody chose and nobody tunes on, so that Adamic's speed claims survive people optimizing against them (#re2xhwa). The holdout runs only at a release or before a claim is made, and no change may be tuned on its numbers.

## The rule

Every program of the Computer Language Benchmarks Game that has a Node.js entry, minus the ones the everyday suite in `bench/` already covers: n-body, spectral-norm and binary-trees. For each, the game's first Node.js entry: `<name>.node`, or, where there's none, the lowest-numbered `<name>.node-<k>`. Not the fastest, and not the one that suits Adamic.

The source is the game's own archive of every program, `public/download/benchmarksgame-sourcecode.zip` (blob `05648fc9a0d6`, sha256 `aabcf6726cdc14f0f45b99e5daba48584f94bbb48883fd3711a1d040474d1cb4`), in its repository at https://salsa.debian.org/benchmarksgame-team/benchmarksgame, commit `40296663ed350d5fe4a6ab5e367bab61cb77c219` (March 7, 2025, the head of the default branch when this was ported). The repository's `bencher/programs/` holds only the sample programs of its measuring tool, so the archive is where the game's programs are. Its `README` names the game's ten active programs: binarytrees, fannkuchredux, fasta, knucleotide, mandelbrot, nbody, pidigits, regexredux, revcomp and spectralnorm. Each has a Node.js entry. The archive also holds `nbodyinprocess` and three `sample*` directories, which the README doesn't list as programs of the game, so they're out. Taking away the three the suite covers leaves seven.

## The programs

Each port keeps its program's algorithm, data structures and output, and changes only what the language requires, with a comment marked `Adamic:` where each change happens. No change was made for speed, in either direction. Every source file carries the game's revised BSD license and names its source file and revision.

Changes every port shares, so they aren't repeated below: `var` becomes `let` or `const` (0.1 has no `var`); an untyped value gets its type; an element read under `noUncheckedIndexedAccess` is `T | undefined`, so a read used as a value carries `?? panic(...)`, and every one of those indexes is in range, so none fires; the size the original read from `process.argv[2]` is fixed in the source at the game's size. That is a choice, not something the language forces: `programArguments()` from `'adamic'` would read it. Fixing it keeps the game's sizes and leaves a run nothing to get wrong.

Three programs read fasta's output on stdin in the game: k-nucleotide, regex-redux and reverse-complement. Adamic has no stdin yet, so each port reads the same bytes from a file whose path is its first argument, `programArguments()[0]`, through `readTextFile`, and consumes them as the original consumed stdin: lines for k-nucleotide, the whole text for regex-redux, 16,000-byte reads for reverse-complement. A missing argument or a file that can't be read panics with why, to stderr, exit 70. The file is made outside the timed run, as the game makes it ([inputs.json](inputs.json), below), so fasta's generation is never inside a timing.

Every comparison is port against port: Node runs the same `.a` file through `oracle/node.mjs`, with the same file argument where there is one (`node oracle/node.mjs bench/holdout/revcomp.a <file>`), never the original JavaScript. The originals of fannkuch-redux, k-nucleotide and regex-redux spread their work over worker threads or a cluster of processes; their ports run it on one thread, so the original's parallelism is gone in both runs and neither side gets more cores.

[inputs.json](inputs.json) says, for each program that reads a file, how its input is made: `generator` names the program that writes it, `fasta` for all three (fasta.a, run with `size` as its argument), and `size` is the game's n for that program. The comparison tool builds fasta.a, runs it natively once at each size before any timing, keeps its stdout as the file, and passes that file's path as the program's first argument to every run, native and Node alike. The ports used to generate fasta's output inside their own run, through a module of fasta's code; that put fasta's generation inside every timing, so it's gone.

## Checked against Node, output only

Nothing here was timed. Each port's only check is that it prints exactly what the original prints. On Node 24.14.1, each original ran as the game runs it (copied to `.js`, with its size as the argument, and fasta's output for the stdin programs redirected from a file), and each port ran through `oracle/node.mjs`, at the same size. Their stdout was compared with `cmp`.

The full-size comparison was running when the porting session ended, and its results weren't recorded. When the three file-reading ports were changed to read their input (November 16), their check was run again in part, and this is what was seen:

- The originals, at n = 1,000 with fasta.node's output redirected to stdin, each matched the game's published output with `cmp`. At the game's sizes they ran to the end on Node 24.14.1, on fasta.node's output for n = 25,000,000 (254,166,745 bytes, sha256 `3fcf4f78104c8a65ef210fe1d469f4e473456c791225f2f1f9114f4986aa09fa`) and 5,000,000 (50,833,411 bytes, sha256 `97197f5957a12f8a859ba7edff6d97994daa18afacd77db21fa68c6f2e447e38`). Their stdout's sha256: k-nucleotide `f8c042fe770dda8f870b967605ea40ca2e353f2bdf92e89a327209dd31d445c7`, regex-redux `a37e6da1d43b332d5c0f4fc25b76090e9095d4c97c25f1a7186385e87706e4af`, reverse-complement `e5730d4fd55c464f276e5c6062c80f46e0a735281de15d8c957e2731a9baf70e`.
- reverse-complement's original, given a 32,000-byte input, two whole reads, prints only up to the last section's header: Node's last 'readable' reads `null` first, and the original returns without reversing it. The port keeps that.
- The ports were not run: this Mac refuses running `oracle/node.mjs` in the repository, and sends it to a Loom job. So no port is yet shown to match at any size since the change, and that check is owed, at n = 1,000 and at the game's sizes, against the sha256s above.

Before that change, at small sizes (fasta, k-nucleotide, regex-redux and reverse-complement at n = 1,000, fannkuch-redux at 7, mandelbrot at 200) each port's output was also compared with `cmp` against the game's own published output files, and all six matched.

No port has been compiled by Adamic here: native builds happen on a remote box. Reading stage 0's lowerer, two ports are expected to stop as NotYet until it learns what they use, and neither is a refusal: mandelbrot hands `process.stdout.write` a `Uint8Array`, which stage 0 writes only for a string (`internal/lower/library_node_process.go`), and revcomp uses `Buffer.allocUnsafe`, `slice` and `indexOf`, which aren't among the `node:buffer` members stage 0 registers (`internal/lower/library_node_fs_buffer.go`). The others may meet stops of their own that only a build will show.
