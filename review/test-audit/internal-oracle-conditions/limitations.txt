Scope and interpretation

The requested historical file commit was 8de93800f4. The mandatory fresh origin/main start was 859dee825a4ef89f5c4ecc0f00e6620ac75c4994. All 13 named functions were discovered and remained in the specified files; none moved or vanished. There are 13 rows after reading the bodies. No pair of top-level wrappers merely supplies a different input to one shared checker. The enum rows have distinct success/refusal versus unknown-call runtime contracts.

The whole package exceeded 90 seconds. Its timeout was not treated as a red baseline or a mutant kill. The selected 12 rows passed clean in 44.789 seconds, and the remaining count row passed clean alone in 65.700 seconds. Production matrices run the 12 rows together and the count row separately. Results outside these 13 rows are unknown. Every unique kill and sacred verdict is bounded to this slice, pending central replay.

The three condition mutant rows are witnesses. Their production-mutant failures are discarded. W1 weakens disagreement by returning an empty difference; W2 weakens conditionLedgerDifference by returning no error. Witness verdicts depend only on those weakening runs. EntriesProvenance and EntriesRuntimeReadiness contain both direct product assertions and built-in mutants, so they retain production verdicts. Their expected checked failures come from Adamic contracts, not Node semantics.

The acceptance row was timed but skipped because stage3/fixtures/entries/expectations.json was absent. Setting ADAMIC_ENTRIES_ACCEPTANCE cannot install a missing worker-authored corpus. No synthetic replacement was created. Its median measures skip overhead and is not an execution-cost estimate. Whole-package WASI skips are outside the requested slice and their SDK was not installed for this unit.

Constraints that cost time or limited the result

The target of three mutants per row implies 39 mutants for 13 rows, while the brief caps the unit at 20 and also asks at most four when each native rebuild is expensive. This unit predeclared eight valid menu mutants: four changes to lowering and four changes confined to JavaScript emission. Eight is below the general cap but exceeds a strict interpretation of the four-mutant rebuild cap. Separate cache directories were used for all eight. This is a process deviation, not evidence for extra uniqueness. No insertion-only supplemental production mutant contributes to a verdict.

The oracle observation key hashes the entire environment, including ADAMIC_MUTANT and ADAMIC_BUILD_CACHE_DIR. A fresh selector therefore invalidates all recorded observations even if a JavaScript-only change leaves native C identical. Count sweeps take cold execution time for every selector. The 20-minute target is consequently difficult for a full 13-row matrix. Individual runs retain the 90-second binary budget and 120-second compilation backstop.

TestCountsAreRecorded sweeps all registered fixtures, input fixtures and additional count generators, then compares one complete table. Selecting a single fixture subtest leaves that table incomplete and produces a misleading parent failure even on clean production code. The count row was therefore run intact rather than narrowed to one purported reacher. Its oracle is a snapshot of Adamic's own counts, not independent semantic authority.

The requested median comes from three separate printed ok lines. It includes all work performed by the test binary, including native building, not go-command compilation. The first loop timing overlapped the separate coverage run; its two later timings determine the median. Count timings differed substantially with cached observations. Warm tools are not proof of warm fixture results.

Production coverage before mutation inventoried 632 nonzero-coverage functions for the 12-row slice. That pre-mutation inventory did not include the count row's larger call closure. The count row subsequently passed a clean coverage run in 45.199 seconds; its additional reached functions are in counts-reached-functions.txt and the union is in all-reached-functions.txt. This is an inventory-order limitation; the fixed menu was selected from production functions already read and reached by the 12-row inventory, and was not adapted to kill results. Native runtime C functions and toolchain internals are not exhaustively inventoried.

Subsumption based on one shared mutant is evidence of overlap in this sample, not a deletion recommendation. The faster subsumer is named with its independently measured median. There is no repository-wide uniqueness claim and no other package's tests were run.

Empty-answer probes are distinct from production mutants. Lower returns nil,nil; native.C and JavaScript return empty strings. Nil lowering is run one row at a time so a Go panic cannot hide later rows. Each observed applicable entry result is retained. Lower probes do not apply to constructed-IR readiness, and JavaScript probes do not apply to the loop row because JavaScript there is only cache-key preparation. Witness and skipped-corpus rows have null vacuity. A row with multiple compiler entries can pass one empty entry and fail another; the aggregate vacuity flag records that a checked entry passed and entry_probe_results supplies the qualification.

All production and test sources are restored before the evidence-only commit. Standalone M*.diff files apply to the starting commit without the switch and each passed go vet in its changed package. scratch-switch.diff plus switch-helpers.diff reconstructs the temporary switch and includes the explicitly permitted witness weakenings. Raw logs are gzip-compressed. Assertion line references in rows.json are mapped to origin/main; raw logs preserve scratch locations.
