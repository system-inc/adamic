## Code under test and oracle

The scoped rows construct products. They call formatfilesOracle, formatfilesPreparedPort, formatfilesUnsanitized and formatfilesPreparedMutant. They do not execute the resulting products or compare their answers. Their expected answer is successful construction, enforced by self-written helper checks. GoOracle invokes go test -c but does not run Go cohere. The code under test for these rows is the construction itself, so S01-S04 use the brief's setup-check exception for breaking that construction. The underlying formatfiles port is the .ts source, never the Go cohere oracle. M01-M08 change only that port. The oracle for the package's execution family is independent Go cohere. Neither Go cohere's source nor its adapter was edited. These distinctions were stated before any mutant.

functions.json is the pre-mutation static declaration inventory. reached-construction-functions.json identifies the scoped rows' package-local call paths. Package helpers are reached during construction, while the port functions are compiled but not executed by these rows. Treating compiled code as dynamically exercised would be incorrect. The independent port sources include the driver helpers, enumerate/walk functions, DiskTree support and Go-compatible string/path helpers; their dependencies are the unchanged gitignore port and Adamic compiler/runtime. Complete dynamic runtime reach is not claimed for build-only rows.

## Brief ambiguities, costs and limits

The brief calls this a 15-row unit, but its family rule makes it four rows. The functions with Native and named-mutant suffixes share one preparation checker and have no additional assertions, so counting them separately would fabricate independent defenders. Native and NativeUnsanitized use different construction recipes and stay separate. The GoOracle row builds the external oracle rather than checking port output, which the external-run label would obscure.

The mutant suffixes look like witness tests, but these functions only prepare built-in mutant products. They never require disagreement. Their proper classification is setup-check. The actual disagreement checks live in the shard family outside the requested slice. Production mutations alone cannot judge the construction promise; the explicit setup-check exception permits S01-S04 edits to construction helpers. None alters expected Go cohere answers.

The general instruction to mutate only the port would conflict with judging a build-only setup row unless the later setup-check exception is applied. This audit uses that exception explicitly and keeps source mutants and construction breaks separate. Likewise, probes need to follow each scoped row's actual entry. Using only a no-output port probe would conceal whether the row even runs that entry.

The source selector allowed one switched build per existing product recipe, not one binary for every recipe: the package deliberately builds 12 built-in mutants, a neutral sanitized product and an unsanitized product. Standalone diff validation necessarily rebuilt each distinct port diff to prove it compiles. The four-mutant limit for an unswitchable port did not apply because the selector worked. Source mutations were planned from the inspected code, then observed; none was chosen after seeing which test failed.

The named starting reference 8de93800f4 was older than fetched origin/main. The fresh commit, unchanged requested names and all source line numbers are recorded. Package-wide uniqueness is supported by this full matrix, but repository-wide uniqueness is unknown. S02's package-unique construction catch is recorded without promoting its setup row to sacred. All speed measurements reflect warm cached products and the current 5-core machine; they do not predict cold CI construction cost.

The package's Go-oracle cache inputs omit the construction helper source. S03/S04 therefore required separate cache directories. Without that isolation their changed callback could have been bypassed by an old valid oracle. Source product keys included switched port content and generated C, so port selectors reused the intended product without reading stale compiler output. No compiler mutant was planted.
