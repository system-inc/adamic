The numbered wrappers all call the same shard checker with an ordinal and are one family. The Union row has extra census, duplicate/missing-range and invalid-selection assertions, so it remains its own row under the brief's distinct-assertion exception, despite the usual shards-plus-union example. Lowered and native wrappers use different preparation stages and form two families. Exact members are listed in scope.json and rows.json.
The numbered family dispatches several kinds of work: batch comparison, raw-input comparison, three built-in mutant witnesses and four throughput units. Its production verdict rests on actual port-output comparisons, not failure of witness preconditions. W2 separately weakened the guarded comparison and made all three built-in witness members fail. Go-only and Prettier-only throughput members are not port empty-answer observations. The raw empty-input member 344 legitimately passes P1 and is reported as a vacuous subcase.
The brief permits at most four mutants when rebuilding stage1 products, overriding the approximate three-per-row target. Four production mutants cover quote handling, digit recognition, fractional normalization and identifier boundaries. A file selector allowed a single instrumented build per product; standalone source diffs were separately built for replay validation. There were no compiler mutants, so separate compiler cache roots per production mutant were unnecessary.

Findings and limitations:
M1, M2 and M3 are each caught only by the numbered family in this package. M4 survives every test. The saved survivor input and outputs show U+0080 followed by 1.000px preserved by the original port and unchanged Go oracle, but normalized to 1px by the mutant's Node and rebuilt native products. This is an observed unguarded boundary, not an equivalent candidate or a claim about all Unicode behavior.
Three preparation rows pass without the promised artifacts. They can still reject explicit builder errors; the untrue verdict concerns the construction mutations actually tried, not a proof that they can never fail for any reason. GoAnswers checks clean completion without verifying answers, and passes empty input. Setup rejects a wrong shard census but passes an empty preparation entry.
The user requested every claim be demonstrated. File/line references in rows.json and menu.json use the starting commit. Raw scratch logs naturally contain shifted lines; the report maps those lines back to the base using the scratch unified diff. Commands and caches are stored in the invocation metadata. Evidence command strings are descriptions; use the metadata argument arrays and quote -run patterns when replaying in a shell.
