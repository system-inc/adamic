Private brand checks do not run natively. Stage 0 refuses `in` before a binary exists, so this is not an oracle fixture. The fixtures that do lower agree with Node.

source:
class Box {
    #secret = 1;
    has(other: object): boolean {
        return #secret in other;
    }
}
class Child extends Box {
    #secret = 2;
    hasOwn(other: object): boolean {
        return #secret in other;
    }
}
const box = new Box();
const child = new Child();
const other = new Box();
console.log(box.has(box) ? 'yes' : 'no');
console.log(box.has({}) ? 'yes' : 'no');
console.log(box.has(child) ? 'yes' : 'no');
console.log(child.has(box) ? 'yes' : 'no');
console.log(child.hasOwn(child) ? 'yes' : 'no');
console.log(child.hasOwn(box) ? 'yes' : 'no');
console.log(box.has(other) ? 'yes' : 'no');

Node exit 0, stdout:
yes
no
yes
yes
yes
no
yes

A subclass instance carries the base brand, and the derived class's own #secret is a different brand: child.has(box) is yes, child.hasOwn(box) is no.

native:
Adamic 0.1 refuses in; an object's shape is known; use a discriminant, or a Map

Exact private brands are part of the unimplemented constructor-object model (docs/class-features.md). What does run is same-spelled private fields and methods in a base and a derived class, accessed from arrows inside instance methods. That case is class_features_distinct.a and agrees with Node.
