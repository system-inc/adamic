## Ambiguities, corrections and costs

- The brief supplied an older reference commit, 8de93800f4, but also required a fresh origin/main. The fetched start is 09fe4b54. All file locations and mutation lines refer to that actual start, recorded in origin.txt. None of the 13 requested names disappeared.
- The brief calls these 13 rows, then requires all shared-checker input variants to be grouped. Six functions call compareExecutionCases with different input builders. They are one family here. The external Boolean chooses live versus stored expectations, so that family has two oracle kinds. Functions with extra assertions, direct run/budget checks, provider storage mutation or stateful loops remain separate. Family member costs are retained for central review.
- Whole-package uniqueness must ignore a witness's production failures. Oct6Mutants can fail because its clean control was broken. Such a failure does not demonstrate the witness comparison. Only W01, which makes both mutant-result comparisons report agreement, establishes the witness verdict. All seven built-in mutants then fail with 'mutant survived' at origin lines 69 or 110. W01 is a permitted harness weakening, not a production mutant or probe.
- The menu's 'swap two arguments' is applied to the two existing opSplit branch targets, swapping the primary and alternative destinations. M06 drops the complete capture-clear loop, leaving no unused loop variable. M12 removes the inner string clone while retaining the outer slice clone; it changes provider aliasing, not the test provider or Node oracle.
- The first selector used a Boolean helper for the rune-valued subtraction endpoint M17. It did not compile. All initial standalone diffs had already passed vet. The rejected build logs are retained under instrumentation-build-errors; no result from those logs is a kill. The corrected selector passed vet, and all matrix commands were rerun. audit.py contains the corrected version and skips timing reruns because those clean timing runs had succeeded.
- Go's binary timeout produces a panic. M09 therefore needs isolated reruns just like M10's out-of-bounds panic, but a timeout remains unknown, not a semantic kill. Test262's 127,369 cases can generate very large failing output when lastIndex or greedy behavior changes. Large logs are losslessly gzip compressed after execution; the commands still show their original .log destinations. The timeouts cost approximately 180 seconds together.
- The brief does not say whether compilation is preparation or an entry for matcher execution. Both interpretations are covered: PExec probes the execution entry, PRun the direct boundary entry, PParse the syntax entry, and PCompile, PCompileUTF16 and PCompileProperties separately probe public compilation calls. Compilation probes return nil,nil and panic at real callers; those callers were run separately to prevent later rows being lost. Probes use an environment guard to avoid unreachable-code vet diagnostics, and are replayed with ADAMIC_MUTANT equal to their ID. They never contribute to sacred or subsumed verdicts.
- TestNodeAgreement checks error presence rather than the returned AST. Node-accepted patterns therefore pass PParse's nil,nil return, while rejected patterns fail. This is recorded as vacuous_subcases, not whole-row vacuity. Its syntax oracle is appropriate for acceptance, but it provides no evidence that successful parsing built a usable tree.
- MatcherTest262Executions does not run Node during the test. Its expected spans were extracted with Node24 from test262 7ab7fafa. It is external-authority, not external-run. One stored successful capture [0,10] was independently checked against live Node in authority-check.log. Extraction coverage omissions documented in MATCHER.md are outside this unit.
- M15 makes the provider-string row print 'missing property silently compiled' despite a non-nil error. The assertion actually requires UnavailablePropertyError; it correctly rejects an unrelated syntax error. The diagnostic wording is misleading, and the row's oracle includes that self-written error-type assertion alongside Node output comparisons.
- Subsumption is a fixed-menu hint, not a recommendation to delete tests. StepLimit rests on two catches, ProviderStrings on five, Oct6Loops on ten, and NodeAgreement on one. The execution family costs 0.885s, more than its subsumed loop and provider rows. The defender decides which cost and coverage tradeoff to retain. StepLimitBoundary and TestFlags are the cheaper named subsumers for the two other rows.
