Implementation details and coverage
===================================
Class decimal escapes now enter Annex B legacy-octal decoding independently of
capture count, with backreference handling still excluded inside classes. A Node
sweep holds 1,536 octal cases plus the cohere pattern-620 witness: 1,537 comparisons.
The order check follows observed V8 saturation at INT_MAX, not the cohere report's
double-rounding inference. Exact arbitrary-width AST counters are retained. There
are 432 syntax comparisons spanning INT_MAX, 2^53, 2^63 and 2^64, in legacy/u/v.
The native fixtures hold the non-nullable large-bound match results. Huge nullable
repetition performance was not optimized or exhaustively covered; bounds above
uint64 retain the existing loud native refusal. This is not a claim of exhaustive
large-bound execution coverage.

One follow-up is blocked, not implemented: Node immediately prints true for
new RegExp('(?:){9223372036854775808,9223372036854775807}').test('').
The accepted AST retains its reversed exact counters. Code inspection of the C
repeat instruction shows it cannot exit below minimum and cannot enter the body
at maximum, so this nullable case risks an extremely long execution followed by
a different eventual result. That eventual result was inferred from the bytecode
conditions, not observed by running billions of iterations. A proposed narrow
NotYet guard for reversed saturated ranges with possibly empty bodies was rejected
by automatic approval review as a new behavior restriction beyond the specifically
authorized parser/cohere fix. No refusal or test from that follow-up was applied.
The consuming cohere witness remains held to Node; this nullable variant is not
covered by the zero-disagreement totals and needs approval for the extra restriction.

The C set operation sorts, then compacts equal endpoints. Equal endpoints have no
capture side effects inside a class, so removing duplicate choices preserves order.
This also covers duplicates introduced by Canonicalize and repeated string operands.

The cache lives in adamic_string_index, not on a RegExp, so it does not retain input
strings. The full view is separate from the BMP-only view (which direct code-point
reads assume has no supplementary characters); it aliases that view for BMP input.
Non-BMP decoding preserves both surrogate units and lone surrogates. Heap release
frees the view, and existing in-place append invalidation discards it before writing.
Ownerless stack pieces keep an explicitly freed temporary decode. The cache fixture
holds mixed BMP/supplementary/lone-surrogate input, repeated reads, append, slices,
replace, split, search and empty input to Node. Existing string-index/view tests pass.

The assignment check recognizes every assignment token and both property/index
targets. Twelve TypeScript-valid string dictionary assignments are tested: missing
and existing names, +=, &&=, ||=, ??=. Adamic 0.1's earlier Refused for &&= and ||=
is preserved; ??= already stops with generic NotYet before operands are lowered.
Supported lastIndex += updates remain admitted. Numeric assignments to string-valued
groups are tsc errors and were not built for this unit.

Main 50045bd already contains the heap-frame free. Item 5 adds its missing guard,
not another free. The exact supplied fixture is unchanged in behavior. Its failing
unanchored search is intentionally expensive under sanitizers: the ordinary
one-minute leak run timed out. It now has its own three-minute process bound,
matching source Node, JavaScript backend, sanitized and release native executions,
then Linux LeakSanitizer or macOS leaks. Its counts join the ordinary counts gate.
No edit to internal/oracle/oracle_test.go was needed. Current Linux observations:
sanitized comparison 110.611 s, release 26.986 s, leak check 92.737 s, all exit 0;
test 236.651 s. The native release standalone control took 20.001 s on an earlier run.
