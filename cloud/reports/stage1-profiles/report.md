## What is implemented locally

cmd/adamic-stage1 builds only the parse and lint drivers. Ordinary adamic build
still selects ThinLTO without a profile. Native Options has Profile and
ProfileGenerate fields. Flags adds profile options only to native, uncounted,
unsanitized release builds. LinkFlags carries the entire list, including
-ffp-contract=off and -fno-optimize-sibling-calls. Direct runtime compilation
with an unverified profile is rejected.

The parse driver is reconstructed from the earlier batch 8 parse-only driver,
using relative imports. It still builds the parser, line table and parent map,
without rule traversal. A new --ast mode dumps the whole tree from that same
binary, so the actual timed executable can be checked against Go. All newly
added Adamic source files use .a. The lint driver remains the existing
stage1/cohere/lint/main.ts. No emitter or lowering code is changed.

stage1/profiles/regenerate.py builds each instrumented driver, runs its fixed
training list, merges with llvm-profdata --text, writes the text profile and
manifest beside the driver, then builds the profile output. No profile was
hand edited. The two committed text profiles were generated by this script
from the exact emitted C and embedded runtime recorded in their manifests.

Training is the 38 top-level TypeScript service files at the pinned checkout
050880ce59e30b356b686bd3144efe24f875ebc8. training.json names every path and
SHA256. benchmarks.json names all 77 compiler files and hashes. Training does
not include any of those paths or identical file contents. Regeneration and a
Go test reject path and content-hash overlap. Added benchmark corpora must be
registered in that list before any new speed claim. No service-file speed
claim is made here.

The build checks the exact emitted C hash, all embedded runtime C/header bytes,
text profile hash, target, compiler identity and release flags. It uses no
timestamp. A mismatch produces one line saying it uses plain ThinLTO, before
any -fprofile-use argument reaches clang. -Wno-profile-instr-out-of-date is
only added after that check passes. Valid text is converted to an immutable,
hash-addressed indexed copy with the local llvm-profdata. That path gives
runtime.a's existing flag-based cache key the profile's content identity.

Text is stored because LLVM indexed formats change across versions. Conversion
uses the receiving toolchain. This does not claim Linux LLVM 20 profiles can
be consumed safely by a different Apple clang without regeneration: target
and compiler checks are conservative, and host-specific profile directories
select the matching version. Apple clang was not available for execution here.
The compiler identity currently includes its installation directory, so a
changed tool installation can also require regeneration.

with independent cold caches did not: the real parse binaries differed at
