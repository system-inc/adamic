# CSS parsing and design system access

Each helper owns one `.a` file. `css_model.a` contains only adapter types. No shared harness, registration generator or compiler source changes.

`parseCSS(original, dependencies)` accepts a byte string: each JavaScript code unit represents one UTF-8 byte, in 0..255. It returns a flat arena and ordered root indices, or a syntax error with the exact Go message and byte offset. The caller supplies encoding and decoding. Passing an ordinary Unicode JavaScript stylesheet directly violates this adapter contract. A leading EF BB BF is replaced with one ASCII space, matching actual Go even though its source comment discusses preserving length.

The parser owns comment and quote routing, ordinary whitespace collapsing, custom-property raw scanning with its independent bracket stack, body-less at-rules, nested blocks, parentheses, trailing at-rules, missing-brace errors and license-comment hoisting. Node records carry all relevant text, importance, value presence and child-list presence; child edges are numeric indices. The finished node array is a readonly view. Context is always nil in ParseCSS's Go output and is omitted from this adapter. No half-built arena is returned on failure.

`CSSDependencies` supplies separately owned ParseAtRule, parseCSSDeclaration, parseCSSString, StyleRule, Comment and whitespace behavior, plus Go-compatible byte-string trimming and UTF-8 decoding. Constructors must return fresh zero-filled records and fresh child arrays. Declaration results distinguish missing from present empty values. String errors preserve Go's message and offset. This unit ports the parser state machine, not those dependencies. Wiring their independently owned ports to this adapter remains integration work.

The differential oracle wraps the real Go dependencies without changing their results. It records exact buffer/colon arguments, string-start/quote arguments and trimming observations. The test adapter returns those observations only for matching arguments; unexpected arguments produce different semantic results. Style/comment creation and UTF-8 decoding are test-only adapters. Parser results are independently computed by actual Go ParseCSS, never returned from a table keyed by parser input.

`designSystemDeclineMessage(rule, entryPoint, errorPresent, errorText)` reproduces the shared message exactly. Empty entry points omit the location clause. A nil Go error renders `<nil>`, distinct from a present error with empty text. The caller supplies the error's already-rendered Go `%v` text; arbitrary custom error formatting is outside this helper.

`loadedTheme(system)` returns `system.theme` unchanged. The adapter uses stable numeric handles with -1 for nil; the caller retains the theme arena. The system must be initialized and nonnil. Tests compare nil and two distinct handles, mutate the selected theme to prove aliasing, and check the stored handle is unchanged.

All six consumer corpora contribute 157 actual runtime source fixtures. CSS comparisons also include the 91 positive and 11 negative inputs recorded from Tailwind 4.3.3, raw custom-property values, nested blocks/parentheses, escaped separators, comments, quotes, Unicode/NUL, CRLF, BOM offsets, missing braces and malformed endings. Source Node, emitted JavaScript and ASan/UBSan native must match real Go. Compiling semantic mutants prove every helper's comparator can fail.
