# Consumer integration

The existing id-length consumer is parked on codex/lint-wave1-02-land and is absent
from current main. id-length.patch wires its exceptionPatterns to the real constructor
module and removes its explicit regex refusal. The patch was generated against that
origin branch and must be applied by integration with the shared registration foundation.
No shared context or registry file is introduced by this unit.

no-inline-comments is absent from current main and every fetched rule directory.
Its ignorePattern consumer calls new InlineCommentIgnorePattern(source) once per
configuration, then ignores(body) with the existing inner, trimmed comment text.
inlineDirective exports its fixed table literal for the block-comment directive gate.
inline_rule.a implements the complete comment predicate over a handed SourceFile
view and declares numeric kind 307 in inline_rule.json. Its 54 fixture comparison
uses Go-projected comment geometry and empty-JSX facts, not finding answers. The
shared comment adapter and independent stage1 JSX geometry remain integration work.

no-warning-comments is wired directly through the existing production comments.ts.
The manual folded-scalar search and decoration matcher were removed; matches now
uses the cached runtime constructor. Quoting and comment geometry are unchanged.

The shared legacy portFiles test copier omits the new regex module imports, and its
old fold-matcher mutants target removed code. Shared harness integration remains
#zmh9v36. Those files were not edited. The owned tests load production sources directly.

The private testdata/id_consumer snapshot is copied from a7da631ee2babef8753dd72d8dfdf3e07ba50832
(codex/lint-wave1-02-land), with the patch applied, a structural test context, and
imports adjusted for the test directory. Grapheme tables and non-regex rule logic

one capture boundary. This unit does not publish a second registered id-length rule.
