## Read-contract reconciliation (#mpg3abq, priority step 27)

The mandatory `declarationAnswer -> askFile(ReadsOtherFiles)` channel cannot serve cohere's five initial proving rules, which declare no program reads. Their descriptors now match those declarations and their consumers use the narrow questions below. The full foreign declaration channel retains its read guard, including when asked through askNode; the narrow questions replace those payloads in local consumers. Implementation is in this working unit; certification results will be recorded after the paired package benchmarks and proof runs, not inferred from compilation.

| Narrow answer | Channel and required reads | Exact checker input and payload | Proving rule / confirmed consumers |
| --- | --- | --- | --- |
| `symbol-identity` | `ask` / `askNode`, no program reads | `GetSymbolAtLocation`; presence and run-scoped ID only | `preserve-caught-error`; the symbol consumers in waves 16, 29 and 30 |
| `shorthand-value-identity` | `ask` / `askNode`, no program reads | `GetShorthandAssignmentValueSymbol`; presence and run-scoped ID only | `preserve-caught-error`; shorthand consumers in waves 13b, 16, 29 and 30 |

The library provenance question does not read compiler options. The separate `IsSymbolFromDefaultLibrary` helper follows cohere's helper, which reads compiler options as well as the default library. At this pinned cohere revision, `nexus/correctness-no-uncleared-race-timeout` declares both; the audit's default-library-only statement describes the narrow provenance requirement, not the current upstream rule descriptor.

Wave 07's `no-undef-init`, `prefer-rest-params`, `react/jsx-no-undef`, `@typescript-eslint/prefer-for-of`, and `@typescript-eslint/consistent-indexed-object-style` remain consumers, not ports owned by this unit. The last also needs `type-reference-graph`. Native reference tracking, CFG and React compiler analysis remain separate dependencies; a narrow checker answer does not certify those analyses.
