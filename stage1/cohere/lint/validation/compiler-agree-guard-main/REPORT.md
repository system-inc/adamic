# Compiler agreement hang guard on main

Base: `749a69adbfae2a7bf22c1f0436d9ef73345c3070` (`origin/main` at fetch).
Merged `6644c7cc6fb2619892851858a04b815077927265` without rebasing or conflicts;
merge commit `d8b79cbbc5d17c7db69b12669cbd0e459f1999bb`. See `merge.txt`.
Branch: `lint-rules/compiler-agree-guard-main`.

The scanner no longer loses CPU scheduling time from a ten-minute wall budget.
`internal/testguard` re-execs the importing test binary, sets `RLIMIT_CPU`, then
execs the original command in the same child process. The default soft limit is
600 seconds of that child's user plus system CPU; the hard limit is one second
later. Time waiting for a core does not count. The independent 60-minute wall
backstop kills the child's process group and reports `wall backstop exceeded`.
CPU exhaustion reports `child CPU hang guard exceeded`, the command/input name,
CPU consumed and budget. Ordinary exit errors retain their type.

Both `execute` and the shared build/capture helper use this guard. Compiler shard
adapters delegate each backend to the same guard instead of Node's 600-second
`spawnSync` timeout. The two-second parser-refusal probe now counts child CPU;
helper-package refusal probes retain their one-minute budgets as child CPU.
Nested captured `go test` commands use `-timeout=0`, under the child guard.
Regular-file stdout and existing stderr assertions remain in use.
