## Implementation

New rule-local declaration.a is an immutable raw declaration snapshot: upstream kind name, text and parent/name/property/initializer/module links. It contains no Go lint verdict. `declarationIsFragment` implements the production declaration arms: an ImportSpecifier uses the imported property name when present and the local name otherwise; it requires Identifier Fragment from exactly react. BindingElement requires ObjectBindingPattern with a VariableDeclaration parent and checks its initializer through the existing fragment source helper. VariableDeclaration checks its initializer directly. `importModuleName` follows exactly NamedImports -> ImportClause -> ImportDeclaration and accepts only string-like module nodes.

The helper deliberately reproduces Go's object-binding behavior: it does not additionally check that a binding element's property is Fragment. Thus an object-binding element named Other from React still passes this predicate. Adding a seemingly sensible property restriction would diverge from production Go. Import aliases use imported Fragment irrespective of the local name. Wrong modules, wrong imported names, array patterns, absent initializers and missing ancestry decline as Go does.

Named kinds describe symbol declarations reached during semantic analysis; they do not dispatch visitors or decide JSX relevance. Rule listener metadata remains named and unchanged. Existing private initializer/tag fixtures still use their legacy numeric snapshot representation; this is not a shared ParseNode adapter. The stale fragment refusal text now accurately names the source adapter and declaration snapshots instead of claiming a shared numeric-node requirement. No shared generator/harness or bridge files were edited, and no Go regular expression was ported here.
