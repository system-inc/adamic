The parser also needs a representation change before a literal port lowers

Micromark represents a state as func(code Code) State, nil at completion, with
captured mutable frames and mutually referring state closures. The minimal probes
separate three facts:

1. gaps/1_recursive_state.ts: Node prints 35 twice. load succeeds; lower returns
   NotYet with exactly "a function inside a function (a closure)".
2. gaps/2_state_arrow_cycle.ts: Node prints 35 twice. A mutable arrow-state cell
   that its closure captures is Refused by Adamic 0.1 as a reference-counting cycle.
   This is a language refusal, not a compiler feature promised to arrive later.
3. gaps/3_recursive_callable.ts: noncapturing top-level recursive callable state is
   supported. Source Node, the JavaScript backend, native ASan/UBSan and native
   LeakSanitizer all agree on 1 then 0, with zero exit and no stderr/leaks.

The recursive callable type itself is not a blocker. Explicit state/frame IDs,
owned arenas and appropriate weak back references are a possible porting approach;
that complete engine transformation was not done. I did not replace the micromark
parser with an approximate line scanner, hand original parsing off to Node/Go in an
alleged native formatter, or edit compiler-owned files to hide the representation gaps.
