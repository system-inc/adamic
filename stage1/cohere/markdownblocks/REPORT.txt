What was ported

lists.ts ports cohere's entire list/list-item document construction: sibling
marker alternation, initial/continuing/Git-friendly numbering, ordered-marker
scanning without regex, number capping, alignment decisions, task boxes,
tight/loose and nested-list blank lines, code-required indentation and the HTML
column exception. Its inputs explicitly carry the caller's AST/path facts.

The native document renderer covers the document operations actual Markdown
uses: text, concat, indent, string/width/root alignment and dedent, groups and
expanded states, fill, if-break, literal/hard/soft lines, labels, trim and break
propagation. Unknown operations panic. It is not claimed as the complete general
Prettier document engine: line suffixes and indent-if-break are not implemented.
Child edges, group identity, commands and indentation roots use numeric IDs in
owned arenas. The implementation has no strong owning cycles or nested closures.
The command stack is owned by its class; indentation generation returns data to
its caller rather than mutating the caller's array. Cohere caught and guided these
ownership/API refactors, along with a shadowed name, unused initializer and
multiple-classes-per-file finding. Final checks have zero findings.

Text display width is an explicit component input. Go's actual StringWidth
supplies it in fixtures. Unicode width remains a separate service to port;
ASCII list/task prefixes measure themselves. No width approximation is claimed.

The list fixture bridge parses and preprocesses every document using actual Go
cohere. It wraps list/word outputs in transparent labels, then captures child docs
and list/path facts. Every collector result is compared to the actual unmodified
Go Markdown formatter with embedding off. Fixtures are serialized before Go
PropagateBreaks mutates groups, so native propagation is exercised. Native
replaces all list labels with its own list constructor and eligible word labels
with the prior inline slice, and lays out the entire document. Ignore contents
remain original raw docs as Go specifies. Source Node and backend run this same
native component implementation; the exact pinned fork's own document printer
runs the original canonical document as another external check.

There is no runtime Go/Node call in native code. Go supplies unported parsing,
non-list block printing, AST/path facts and inherited alignment in the test
harness. The fixture driver is not a native Markdown-file formatter. Full
CommonMark list recognition and the tokenizer/container state engine remain
unported; orderedMarker is the printer's prefix-info scanner, not that engine.

   supported. Source Node, the JavaScript backend, native ASan/UBSan and native

The recursive callable type itself is not a blocker. Explicit state/frame IDs,
owned arenas and appropriate weak back references are a possible porting approach;
that complete engine transformation was not done. I did not replace the micromark
parser with an approximate line scanner, hand original parsing off to Node/Go in an
alleged native formatter, or edit compiler-owned files to hide the representation gaps.

Artifacts and what the tests prove

GAPS.md records the exact contracts, proof programs, scope and reproduction.
audit_test.go walks every .md/.markdown/.mdown/.mkd file, case-insensitively, in the
checkout and initialized submodules, skipping only .git. The 77 generated documents
cover ATX/setext headings, all list marker families through five nesting depths,
fenced/indented code, block quotes, tables, HTML, thematic breaks, front matter,
typed fences and the two embedding witnesses. Every document is formatted in
both auto and off modes by the real Go and JavaScript printers. The off output is
compared byte for byte. The observed auto discrepancies have a named whitelist;
closing an old discrepancy, adding one, or losing an input fails the audit.
The whitelist is evidence of an incomplete contract, not a full-format parity gate.

Three output-only Go-printer mutants (not Adamic block-printer mutants)

Each mutant overlays one real upstream Go source site, builds a Go printer,
formats the entire census, exits zero with empty stderr and no formatting errors,
and is caught solely by comparing its off output with the original fork's.
- Heading prefix: increase printed ATX depth by one. Caught by CLAUDE.md at byte 1.
- List marker: use + instead of the canonical even-sibling -. Caught by CLAUDE.md
  at byte 618.
- Fence length: increase the minimum backtick fence from 3 to 4. Caught by CLAUDE.md
  at byte 3022.
The submodule itself was never edited. There were no three native block-printer
mutants because that printer was not built. The closed callable probe is separately
held by the three-way compiler oracle and sanitizers, not by these Go mutations.

Measurements, and no native formatter claim

The final preflight recorded Go 111.5 documents/s, 3 process runs 25.642425s, and
Node running the pinned fork 106.5 documents/s, 3 runs 26.842446s. Each document
computes both auto and off, and input JSON decoding, formatting, output JSON
encoding, startup and captured output are included. Builds are excluded; every
measured result is checked against its corresponding baseline. These are baseline
measurements on a mixed-size whole-document corpus. They are not Adamic native
formatter speeds, nor a throughput comparison with one formatting call per text.
No native full Markdown measurement was possible without a completed implementation.

Checks and limitations

Final complete new-package test passed in 97.291s. go vet ./... and gofmt over
cmd/internal/the new folder passed with no output. Six existing runtime fixtures
ran uncached: closures, named_function_values, method_closures, functions,
closures_throw and closures_throw_uncaught. Native/node cache hits were zero.
The first fixture command selected only closures because the other guessed
fixture names did not exist; the corrected command ran the five actual named
fixtures, and both logs are retained below.

No compiler changes or new global oracle fixtures/count rows were made. The new
TS programs are intentionally unsupported/closed probes under the existing gaps
ignore policy; there are no new production TS files for a formatter/style check.
The unchanged inherited inline unit had already passed on this identical main
base and toolchain in the prior unit; it was not rerun against the expanded corpus.
The full repository gate was not repeated: the previous uncached full worker gate
on this machine took about 16 minutes. This preflight folder and its relevant
uncached oracle subset were tested; integration still requires its full uncached
gate before main moves.

Not delivered: the requested native Markdown parser, AST/preprocessing adapter,
recursive headings/lists/code/quotes/tables/HTML/thematic/front-matter printer,
document engine, composition of the inline helpers into that printer, raw-file
formatter driver, full all-oracle native parity, native formatter throughput or
native formatter mutants. The audit does not resolve these prerequisites or
alter the current Go/JavaScript target discrepancy.
