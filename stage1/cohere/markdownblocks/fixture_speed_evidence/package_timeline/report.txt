Best next opportunity (no implementation proposed in this commit)
Bounded overlap of independent nonparallel tests offers the largest measured
wall reduction: most of the 563 s prefix uses ~1 CPU, leaving quota idle. Start
independent heavy tests earlier with an explicit memory budget rather than
adding unlimited t.Parallel. Moving formatter cold work earlier/prebuilding it
addresses a secondary, cache-sensitive serial cost. Tail priority would be the
whitespace policy baseline and the list native canary, which obtain slots late;
preventing layoutOnce waiters from monopolizing slots could advance these. That
can shorten the 125.68 s parallel tail, but its measured opportunity is smaller
than the serial prefix. No counterfactual speedup number claimed: parallelizing
changes CPU/cache/memory contention and needs a separate experiment.
Plain CPU saturation is not the overall cause: average busy CPU equivalents
are 1.90 across the package; most serial non-formatter bins are ~1.0-1.6. Cold
formatter compilation saturates the four-CPU quota, and some parallel bins reach
~3.36, but the package is not saturated throughout. Logical nproc=5 while
cpu.max=400000 100000 caps sustained use at FOUR CPU equivalents.

Event timing caveats and every-test accounting
For EVERY top-level test/subtest, tests.csv and tests.json include RUN time,
first CONT, terminal event time, explicit running/paused intervals, total event
running time (RUN/CONT to terminal event, minus PAUSE), Go Elapsed, paused time
before/after the top-level serial barrier, parent and source-backed wait notes.
Requested event running time is literal; it is not CPU or accurate body time
for buffered subtest completions. E.g. initial_BOM reports 0.26 s but its PASS
is delivered at parent completion. Go Elapsed is rounded to 0.01 s; parent
reported elapsed excludes waiting for PARALLEL children (probe parent reports
0.00 s while its event lifetime is 8.303 s). Parent intervals also include waits
inside synchronous t.Run. Running-child overlap/outside-child fields are literal
event geometry only, not exclusive CPU/body time. Do not double-count parent
and child durations or sum them as package wall. Every test's internal exact
wait is unobservable from these events; source notes identify dependencies,
with exact PAUSE waits and sampled subprocess activity supplied separately.
